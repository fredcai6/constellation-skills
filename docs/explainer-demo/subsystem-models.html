Detail (from the Cartographer packet)

Responsibility

Shared dataclasses, type-safe data structures, and exception hierarchy for the data layer. Used by src/data/, src/simulation/, and other data-domain packages.

This package is not purely passive dataclasses: performance_metrics.py and strength_calculator.py read through src.data.database.DatabaseManager for the stale Monte Carlo simulation path.

Key Modules

data_models.py Core dataclasses:

  • Driver — driver information with full_name property
  • Weather — weather data with __post_init__ validation
  • Session — session metadata with SessionType enum
  • LapTime — lap data with theoretical_best calculation
  • TelemetryPoint — single telemetry measurement
  • SessionStats — per-session collection statistics
  • CollectionStats — aggregate collection results
  • PracticeFeatures — extracted practice session features
  • RaceResult — race finishing data

performance_metrics.py Driver performance metrics: qualifying, race, championship metrics, and recent form with exponential decay. Uses DatabaseManager to read historical results. Used by strength_calculator.py.

strength_calculator.py Weighted scoring model (0–100 scale) from qualifying performance (25%), race performance (40%), recent form (25%), and championship standing (10%). Uses DatabaseManager and produces driver strength ratings consumed by the Monte Carlo simulation path.

exceptions.py Typed exception hierarchy:

F1DataError (base)
  CollectionError
    SessionLoadError
  DatabaseError
  ValidationError
  DataProcessingError
  ConfigurationError

Notes

  • performance_metrics.py and strength_calculator.py appear to feed src/simulation/ (the MC simulation path) rather than the evo pipeline
  • The exception hierarchy is used across src/data/ and src/models/; src/latent_power/ and src/evo_predictor/ have their own exception types
