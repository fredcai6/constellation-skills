Responsibility

F1-specific side of the live evo path. Owns: database-backed race-weekend feature construction, compound-prior normalization, module-facing PairBatch adapters, gold training cycle orchestration, sampled runtime manifest composition, CLI command surface, and all post-field-solve output (RacePrediction, fantasy scores, serialized reports).

Does not own: generic solver lifecycle, pairwise training, field solving, or domain-independent Bayesian fusion (those live in src/latent_power).

Key Components

gold_cycle/ — Gold Training Cycle Orchestrates training of all latent-power modules in sequence. Reads configs/evo/gold_defaults.toml for defaults and train/eval split. Supervision (ADR 0008): retro-delta only — no target_mode switch (#303). [uncertainty].lambda_sigma_nll (default 1.0) and optional student_t_nu_sigma (default null → same ν as term A) pass into each module LatentPowerConfig for detached sigma Student-t NLL (term B). Post-hoc enable_sigma_calibration (alpha/beta LOSO fit) remains orthogonal. Gold reports are schema v6 (REPORT_SCHEMA_VERSION = 6 in gold_cycle/reports.py); run_config records lambda_sigma_nll and pairwise_sigma_nll_enabled but no longer target_mode. Per-module uncertainty_diagnostics carries full-eval r_over_sigma_p50/p90/p95/p99 and sigma_mean (#304).

Per-module eval metric honesty (schema v6; issues #323/#324/#326). Schema v6 replaced the semantically-broken pairwise_log_loss (BCE over a Student-t location head) and the mislabeled module_rank_mae_delta_vs_grid_or_recent_baseline with honest, chance-anchored metrics, each reported as (raw, blind-chance floor, skill):

  • rank_mae_vs_actual — predicted order vs the real on-track finishing/quali/start order (per phase, fetched from DB metadata).
  • rank_mae_vs_retro_bt — predicted order vs the retro-BT supervised order (the training labels).
  • pairwise_nll / pairwise_nll_skill — Student-t NLL of the mean head vs a median-predictor floor with the module's own sigma; the nll_skill = floor − raw (nats) is the cross-module-comparable, scale-robust signal that fusion covariance weighting consumes (fusion_training/_train.py block scales use exp(-skill)).
  • pairwise_sign_accuracy — fraction of pairs where sign(mu) matches the winner; floor 0.5.

The blind-chance floor for the rank MAEs is the expected MAE of a uniform random permutation, (n²−1)/(3n), computed per event. The old "delta vs grid/recent baseline" competing-predictor concept was deleted, not renamed. baseline_deltas() was rewritten as skill_vs_chance() (gold_module_cycle.py). Canonical field contract: docs/evo/gold_module_training_cycle_report_schema.md and docs/report_schemas/gold_module_training_cycle.md. Promoted production bundles: params/gold/runtime_bundles/gold_cycle_260612_054059_2018thru2024/ (#440; supersedes gold_cycle_260608_043414_2018thru2024). After manifest assembly, runs backtest_sampled_runtime for sampled_state and oracle_all_states modes (fail-safe: warning on error, no abort); passes results to build_task_calibration_diagnostics to emit per-task sampled_runtime aggregate metrics in the gold report. Produces module bundles, a sampled runtime manifest, and committed reports under reports/evo/. Entry: gold_cycle/runner.py. Config: gold_cycle/config.py. Calibration: gold_cycle/calibration.py. Task calibration: gold_cycle/task_calibration.py. Fusion diagnostics: gold_cycle/fusion_diagnostics.py (pairwise Pearson-r of mean_absolute_rank_error per fusion task; pure in-memory, no DB access, no fusion contract changes; result stored as fusion_correlation_diagnostics in summary and details). Reports: gold_cycle/reports.py.

Parallel fan-out (#356). The three gold-cycle training loops (_train_all_modules — 12 main runs; _collect_loso_fusion_train_rows — LOSO runs; _blocked_calibration_module_rows — calibration runs) and the sampled-backtest phase now fan out through src.utils.utilization.run_jobs under a ResourcePlan resolved once from runtime.utilization (resolve_resource_plan). This is a result-preserving runtime dial only: input-order reassembly plus n_workers == 1 in-process short-circuit reproduce the sequential path. gold_cycle/parallel_jobs.py holds the picklable, spawn-safe job contract: the frozen TrainBacktestJob (train Namespace + backtest-template Namespaces without bundle, plus a stable key) and the module-level run_train_backtest worker, which lazily imports cmd_train_latent_power_module/cmd_backtest_latent_power_module from run.py (avoids the heavy/circular import at module load) and returns only picklable primitives/paths. Imported by gold_cycle/runner.py and gold_cycle/runner_support.py; gold_cycle/config.py validates runtime.utilization against UTILIZATION_LEVELS. CLI: run.py exposes --utilization {background,balanced,max} on the gold-cycle subparser, applied directly post-load via _apply_utilization_hint (bypasses apply_cli_overrides, so it never lands in applied_overrides). Default balanced from configs/evo/gold_defaults.toml.

Module record sidecar (#371). GoldCycleRuntimeConfig gained optional emit_module_record (bool, default false; validated in gold_cycle/config.py). When true, the three backtest template builders (mains in runner.py, LOSO + calibration in runner_support.py) set --emit-module-record on each backtest-latent-power-module invocation; cmd_backtest_latent_power_module in run.py strips record payloads from the backtest JSON (byte-identical when flag off), then spills {stem}.record.npz + {stem}.record.json sidecars next to --output via module_record.write_module_record. Reuse guard requires sidecars to exist when the flag is on; fails fast if a scored event has no record. emit_module_record is deliberately not echoed into details.json/run_config to preserve byte identity of committed reports. CLI override: run.py gold-cycle subparser exposes --emit-module-record (gold mode rejects — sidecars are non-committed training-run artifacts). Default false in configs/evo/gold_defaults.toml. Sidecar contract: docs/evo/module_backtest_record.md.

Split across _assemble.py, _build.py, _config.py, _helpers.py, _memory.py, and _quality.py; public surface re-exported from data_adapter/__init__.py. pipeline.py — Schema v3 Pipeline Loads a schema v3 pipeline_manifest.json, validates fields, hydrates the latent-power module bundle, builds RaceFeatures, adapts to PairBatch, and produces RacePrediction. Entry for the legacy predict and backtest commands.

sampled_runtime.py — Schema v4 Sampled Runtime Manifest-driven multi-module composition. Loads a sampled_runtime_manifest.json, hydrates all configured modules (quali, race-start, race power), runs each through their adapters and the latent-power solver, and fuses module field results using precision weighting. Powers sampled-predict and sampled-backtest. Runtime consistency seam (#369): _run_stage merges the bundle manifest's feature_schema_version (if present) into config_overrides before calling build_pair_batch_for_module; the adapter derives its encoding from the version string. Manifests without this key skip the merge silently (old bundles remain compatible). Quali head anchor seam (#420/#425): after per-module field solve (and before fusion), _run_stage calls _anchor_quali_field when task==quali + driver_quali_power_from_race_weekend + QualiPaceAnchorConfig.enabled. Anchor reads d.allfp_best_raw directly from DriverFeatures — the all-FP min-sector pace field introduced in #425 as the canonical single source (prior to #425 it was reconstructed inline as _nanmin2(qs_best_raw, lr_best_raw)). sigma_pi is unchanged. Both helpers (_anchor_quali_field, _nanmin2) are defined in sampled_runtime.py; _nanmin2 is no longer used for anchor since #425.

fusion.py — Field Fusion Precision-weighted field fusion over ordered module results (fuse_module_fields_ordered). Consumes ModuleFieldResult objects (field solution + uncertainty) from latent_power. Domain-generic fusion logic belongs in latent_power; this file holds the F1 orchestration layer. FusionStepConfig carries per-step covariance_scale, mean_scale, and optional covariance_tension_inflation (additive, default 0.0). Also contains fuse_module_fields_correlated — an OFFLINE-ONLY measurement variant (no production call-site): per-entity GLS fusion with a k×k cross-module error correlation matrix R (Σ_i = D_i R D_i). Production fuse_module_fields_ordered is unchanged. Measured verdict (#373, epic #372): modelling the cross-module error correlation R moves calibration, not ordering — the remaining headroom is in module interactions (#374), not redundancy discounting, which is why fuse_module_fields_correlated stayed offline-only.

fusion_training/ — Static Hierarchical Fusion Training (package) Fits per-module covariance scales from gold cycle artifacts and produces a trained static_hierarchical_fusion config (JSON, written to params/gold/fusion/). Split across _train.py, _calibration.py, _correction.py, _correlation.py, _helpers.py, _manifest.py, _metrics.py, _types.py. _correlation.py (offline; no production call-site): estimate_cross_module_correlation builds R from standardized residuals pooled over events, shrunk toward I; mask_correlation_to_block constructs the cheap-B constructor↔driver block mask. Policy: OOF scipy optimisation (scipy_oof_lbfgsb_v1) on LOSO rows when available, family-specific conservative floors, per-circuit reliability inflation, and tension-based additive covariance inflation. Block scales and tensions are derived from the per-module pairwise_nll_skill metric (schema v6) via exp(-skill), not the retired pairwise_log_loss. Config schema version is 1 (no tension inflation) or 2 (nonzero tension inflation). Standalone CLI: scripts/run_static_hierarchical_fusion_training.py. Offline measurement harness: scripts/fusion_replay/ (numpy-only package; loads #371 per-event module records, reproduces production fusion, scores baseline vs correlated variants; reads the SQLite DB read-only for constructor↔driver mapping; generated records are gitignored artifacts; no production call-site; scripts are not map nodes).

fusion_conditioned_net.py — Context-conditioned fusion net (#375, G2 build) Context-conditioned fusion network for race-day tasks: an antisymmetric ordering head (OddMLP) that conditions the module-field combination on event context, targeting the module-interaction headroom that the offline correlated-fusion measurement (#373) identified as the remaining lever beyond precision-weighted ordering. Build-stage component; not on the production fuse_module_fields_ordered path.

practice_preprocessor/ (package) Aggregates FP1/FP2/FP3 lap data into compound-regularized short-run and long-run pace aggregates (_compound_helpers.py, _compute.py, _lap_pipeline.py, _types.py). Consumes the src.data.protocols.SessionStore typing seam and src.utils.environment for air-density. Laps are split into quali-sim (push) and long-run (managed) buckets before compound normalization; compute_practice_features / compute_constructor_race_features_from_laps take an optional quali_sim_compound_normalizer (#380) routed only to the quali-sim bucket, defaulting to the shared compound_normalizer (byte-identical when unset). Feature normalization is median-relative and unconditional (no config switch): pace-LEVEL features use (value − field_median) / field_median; TIME-MAGNITUDE dispersions/spreads/gaps use value / field_median_lap_time. Missing/degenerate fields fall back to 0.0 (median-neutral); _missing indicators carry absence. No minmax path exists. NormalizedPracticeFeatures also carries allfp_best_raw: Optional[float] (all-FP min-sector pace in raw seconds, lower=faster) and allfp_best_raw_missing: bool; these are populated by _lap_pipeline._allfp_best_raw(lr_best, qs_best) and are the canonical single-value practice pace signal consumed by the quali anchor (#425). See docs/evo/pace_encoding_change.md and docs/evo/practice_preprocessor.md.

quali_pace_gap_history.py — Quali Pace-Gap History Provider Pure DB-backed provider: given (db, year, round_num), returns {driver_id: [gap_round1, ...]} for rounds 1..round_num-1. Gap formula (frozen): (t − field_median) / field_median computed from best valid non-pit Q laps per round. Negative gap = faster than median. nan where a driver has no valid lap that round. Uses one batch DB call (get_quali_best_valid_laps_batch). Returns {} when round_num ≤ 1. Used by both data_adapter/_build.py (full-feature path) and module_adapters/_common.py / _runtime_builders.py (recent-history path). Its compute_pace_gaps is also the median-relative de-unitization reused by spread_target.py (below).

race_pace_gap.py — Race Pace-Gap Observable (#387) Pure DB-backed observable over the get_race_lap_times frame (no FastF1). Derives per-driver race pace gaps in fraction-of-median units. PRIMARY observable integrated_pace_gap: per-lap pace delta (lap_time − lap_field_median) / lap_field_median integrated over ACTIONABLE laps (green-flag + completed) and averaged. Actionability is per (driver, lap) via FastF1 track_status (is_green_track_status — pure-green only; composite codes like "12"/"21" excluded), so a caution-transition lap contributes only its genuinely-green driver-laps. field_median_spike_actionable_mask is the tested no-status fallback (a caution shows as the whole field's lap times spiking together). BASELINE observable finishing_gap retained as a diagnostic only. The PRIMARY-vs-BASELINE choice was measured (run package CANDIDATE_SELECTION.md): PRIMARY gives ~13× blowout-vs-packed dynamic range and caution-robustness; BASELINE collapses and is caution-fragile.

spread_target.py — Event-Conditioned Spread Target s_e (#387) DB-side derivation of the per-event spread scale s_e (the magnitude the retro ordering labels structurally cannot carry — see docs/evo/prediction_ceiling_and_priorities.md §1.3/§9). Frame: expected_gap_ij ≈ s_event · (pi_i − pi_j), s_e dimensionless (fraction-of-median per unit retro power). Estimator (robust-first): s_e = median over driver pairs of (pace_advantage_ij / (pi_i − pi_j)), degenerate |Δpi| < 1e-4 pairs dropped; non-positive/non-finite estimates clamped to a positive floor and FLAGGED (clamped), never silently fixed. Companion pace-vs-finish sign-disagreement rate recorded as its OWN field (never blended into s_e) for the σ work. Race/race_start pace from race_pace_gap.integrated_pace_gap; quali pace from quali_pace_gap_history.compute_pace_gaps. Retro pi (raw field.pi) read READ-ONLY via latent_power.retro_loader (lazy import — no import-time torch dep; preserves the existing evo→latent_power edge, no new direction). s_e is a post-event LABEL (sees the event's own laps); as-of discipline applies to the features that later predict it. Consumed by #391 (quali s_e gap scale for the mean head) and #386/#388/#389 (race/race_start s_e + disagreement rate for σ). Generator: scripts/build_spread_target.py (derived, deterministic).

quali_gap_scale.py — Quali Mean Gap-Scale Expression (#391) Pure, additive, default-preserving module that turns the quali mean head's dimensionless ordering pi into a gap MAGNITUDE via the per-event exchange rate: expected_gap_ij(pi_i, pi_j, s) = s·(pi_i − pi_j) (the phase-agnostic #386 contract function) plus a field-level expected_gaps(pi_map, s, reference='median'). Because a positive s is monotone in pi-differences, the gap expression CANNOT move any ordering KPI (algebraic decoupling — magnitude here, ordering in pi/#375). Prediction-time s_hat_e providers: carry_forward_scale (CF1, last-prior-event quali s_e), same_circuit_prior_year_scale (CF2, same-GP prior-year s_e), and global_constant_scale (the status-quo-ante baseline). No DB/FastF1/torch; consumes a scale value + a pi map only (spread_target.py is the s_e source and is untouched). #386 (Thrust B) measures "excess flip risk beyond the gap" against this function with the LABEL s_e; the #391 mean head feeds it the prediction-time s_hat_e. Measured OOS-2025 midfield gap-MAE (scripts/diagnose_quali_gap_scale.py): the cheap carry-forward variants do not beat the global-constant baseline (honest null), so the shipped default s_hat_e is the global constant; ordering sign-accuracy is identical across scales (flat-ordering confirmation). A learned feature→s_e head is deferred (#375-shaped). See docs/evo/prediction_ceiling_and_priorities.md §9.6.

quali_pace_anchor.py — Quali Head Cross-Channel Pace Anchor (#420) Pure stdlib+numpy production blend function. Single public entry: blend_quali_pace_anchor(pi, anchor, alpha) -> np.ndarray. Implements within-event z-standardized blend of the race_weekend quali head's latent field with a practice min-sector pace anchor: pi'_i = (1-alpha)*z(pi)_i + alpha*z(-anchor)_i. Sign convention: pi higher = faster; anchor in raw seconds lower = faster, negated before z-standardization so both terms share the same sign. Missingness policy: drivers with NaN/non-finite anchor are EXCLUDED from anchor z-stats and receive no anchor term (output kept, no impute); fewer than 2 valid anchor values skips the anchor entirely and returns pi unchanged. alpha=0 is an exact no-op (early return, preserves pi magnitude not just ordering). No domain imports beyond numpy — module-leaf under struct:evo; no new cross-region import. Applied inside sampled_runtime._run_stage on the race_weekend quali head's per-module pi BEFORE fusion (admiral ruling 1), gated on task==quali + driver_quali_power_from_race_weekend + QualiPaceAnchorConfig.enabled. The anchor value read is d.allfp_best_raw directly from DriverFeatures (#425); prior to #425 it was reconstructed inline as _nanmin2(d.qs_best_raw, d.lr_best_raw). Acceptance on the promoted bundle (2018-2024 LOSO alpha=0.5): overall 0.7765 / EASY 0.9058; OOS-2025 overall 0.7616 / EASY 0.9004; alpha=0 reproduces baseline exactly. ACTIVE in the promoted gold bundle (gold_cycle_260612_054059_2018thru2024, #440) — the gold retrain was run with anchor enabled, so fusion and calibration are fit against the anchored pi scale. See docs/evo/prediction_ceiling_and_priorities.md §7.6.4.

module_uncertainty_diagnostics.py — Post-Hoc Uncertainty Sidecar Builds the compact module_uncertainty_diagnostics report (report_type=module_uncertainty_diagnostics) emitted alongside gold-cycle details. Distinct from gold-report modules[].uncertainty_diagnostics (training-time |r/σ| percentiles from latent_power.training). Key Constraints

  • No direct FastF1 calls from any adapter, scorer, or predictor code
  • Same-season full-year compound priors rejected by default in eval/predict
  • src/latent_power must not import src/evo_predictor (rationale in constraints overlay)
  • Unknown module names fail at CLI parsing or registry lookup
  • src/evo_predictor/module_adapters/ (package; registration in _registry.py) is the single registration site for all module adapters. build_pair_batch and build_labeled_pair_batch closures on ModuleAdapter own their full wiring — kwargs assembly, position extraction, config resolution, diagnostics — with no central dispatcher.
  • Ambiguous sparse feature neutrals (adjustment factors whose missing-data fill value sits inside the real observed distribution) require a companion {feature}_missing binary indicator column. When sparse: (0.0, 1.0); when present: (real_value, 0.0). Unambiguous sparse features (support=0.0, share=0.0) do not need indicators — they already sit outside the real distribution.
  • DNF_POSITION = 30. Value 21 misclassifies P21 as a DNF on a 21-driver grid (2026+). 30 provides headroom beyond any realistic F1 grid size.
