**Overall read.** The engine-facing sections are the strongest: the 906-test suite reproduces cleanly (906 passed, 1 skipped, 35.7s), every verb is registered, the confirm gate is genuinely enforced (F-T11), and INV-2/INV-3 are honestly enumerable. The testability weakness is concentrated where the design touches things the suite can't reach: the epic's headline success metric has no reproducible instrument (F-T2, the one BLOCKING) — you cannot tell after ship whether the whole point was achieved. The two "converged panel" recommendations each smuggle in one hard-to-falsify or unbuilt claim: INV-1 is tautological against its own output (F-T1), and S6's executor behavior — the reason the schema exists — is deferred to "first use in anger" on an unbuilt #136 seam (F-T4). The enforcement seams for S3 are named but don't exist as described (F-T3). And S10's hardening list is partly already done: `_collect_changed_files` and the reopen cascade are already tested, so two of its three headline items are mis-specified against the actual test file (F-T5, F-T6) — the real, un-named gap is that the existing git-integration test silently skips without git, which is exactly the seam S5 must guarantee (F-T8). Net: the spec is honest about several of these ("verified by first use in anger" is stated, not hidden), but honesty about a non-falsifiable pathway does not make it falsifiable, and three sections (S3, S6-executor, S10a) rest on test claims that don't match the repo as it stands today.
