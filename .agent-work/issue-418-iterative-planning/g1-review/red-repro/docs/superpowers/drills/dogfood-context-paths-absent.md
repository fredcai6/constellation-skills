# Drill: dogfood-context-paths-absent

- **Lesson / doctrine under test:** `skills/commander/templates/COMMANDER_SPINE.template.json`
  — the `context` step imperative (docs/agents/* + config_ref escape hatch, PR #75) and the
  `execute` step imperative (STATE_NOTE bundled-fallback, PR #86).
- **Failure it guards:** a Commander running directly against the constellation-skills
  *source* repo (dogfooding, not an installed target) finds
  `docs/agents/{ORCHESTRATOR_CONTEXT.md,GLOSSARY.md,engine-config.json}` and
  `.agent-work/templates/STATE_NOTE.template.md` absent — they are generated by
  `install_constellation.py` into consuming projects. With no doctrine, the agent must
  reason through whether confirmed-absence satisfies the condition and locate the bundled
  `skills/<role>/templates/*` fallback unprompted, i.e. improvise around a hole the
  imperative gives no guidance for. Recurred four-plus times across the epic (issues #45,
  #51, #54, #71, #74).
- **Run by:** fresh-context lessons-auditor at `20260706-dogfood-audit` closeout.
- **Date:** 2026-07-07
- **Verdict:** PASS — before-arm reproduced the improvisation-under-uncertainty; after-arm
  followed an explicit sanctioned branch with high confidence. The doctrine text changes
  behavior.

## Scenario

Identical task and repo facts in both arms; the **only** variable is the imperative text the
subagent is armed with. A throwaway Commander subagent is told it is at the `context` and
`execute` steps of a repo that is a skill-SOURCE repo — no `docs/agents/` directory, no
`.agent-work/templates/` directory, but `README.md`, `docs/CONSTELLATION_OVERVIEW.md`, and
bundled `skills/workbench/templates/STATE_NOTE.template.md` all present — and asked to follow
the imperative literally, report each named-but-absent path, what it did to make progress,
and **how confident it was that its action was sanctioned vs. a guess.** Neither arm knew
which arm it was.

The two arms differ only in the imperative text:

- **Before-arm doctrine** (the faithful recurrence state, `git show 363d27a`): the `context`
  imperative names `docs/agents/{ORCHESTRATOR_CONTEXT.md,GLOSSARY.md,engine-config.json}`
  **unconditionally** (only `.agent-work/LESSONS.md` carries an "if it exists" guard), and
  the `execute` STATE_NOTE substep names `.agent-work/templates/STATE_NOTE.template.md` with
  **no** fallback.
- **After-arm doctrine** (current `d442845`, PR #75 + PR #86): the `context` imperative adds
  "Where the repo carries no docs/agents/ overlay at all (e.g. a skill-source repo),
  substitute the closest repo doctrine you can find (README, CONTRIBUTING, top-level docs)
  and record the substitution — do not treat those paths as guaranteed to exist," plus the
  config_ref "sanctioned degradation, not a gap to fix" clause; the `execute` STATE_NOTE
  substep adds "or the bundled skills/workbench/templates/STATE_NOTE.template.md when the
  project has no .agent-work/templates/ overlay."

## Before-arm — improvisation reproduced (verbatim)

The subagent, on the `context` step:

> "Treat the missing project deltas as vacuously satisfied ... I'd substitute
> `docs/CONSTELLATION_OVERVIEW.md` + `README.md` as the closest project-context read ...
> **Confidence: Low-to-medium.** The 'if it exists' clause is explicitly attached only to
> LESSONS, *not* to the docs/agents deltas — those are stated unconditionally. So skipping
> them is genuinely an improvisation the instruction does not license. Reading OVERVIEW as a
> stand-in is my invention; 'the current map' is undefined here, so that read is a guess too."

On the `execute` STATE_NOTE substep:

> "I'd author `.agent-work/<work-id>/STATE_NOTE.md` ... sourcing the shape from the bundled
> `skills/workbench/templates/STATE_NOTE.template.md` ... **The pure guess is *which*
> template is canonical; I'm inferring the workbench bundle is the same artifact under a
> different path, unverified.**"

Closing: "Step 1 gave zero guidance on missing *unconditional* deltas — I invented the
fallback."

This is precisely the documented cost: the agent lands near the right substitution but only
by an **unlicensed improvisation it self-rates as low-confidence and unverified** — the
"reason through confirming absence and locate the bundled fallback unprompted" friction the
lesson names. The before-arm reproduces the rediscovery on demand.

## After-arm — improvisation did not fire (verbatim)

The subagent, on the `context` step:

> "The instruction *explicitly* covers this ... I substitute `README.md` +
> `docs/CONSTELLATION_OVERVIEW.md` for the three missing deltas and record the substitution.
> The missing `engine-config.json` is *separately* blessed as 'absent-by-design ...
> sanctioned degradation.' **Confidence: high. The instruction anticipated exactly this repo
> shape and told me what to do. No invention required — I'm following an explicit branch.**"

On the `execute` STATE_NOTE substep:

> "Take the fallback branch: render `STATE_NOTE.md` from
> `skills/workbench/templates/STATE_NOTE.template.md` ... **Confidence: high. Both the
> trigger condition (no overlay) and the exact fallback path are spelled out and match the
> repo. No guessing.**"

Closing: "Neither step forced me to invent a path — both instructions pre-declared the
skill-source-repo degradation."

The load-bearing behavior — *does the agent have to improvise an unlicensed fallback?* — is
**no**. The confirmed-absence is treated as satisfying the condition, and the bundled
fallback is named, so the substitution is a sanctioned branch, not an invention.

## What the drill proves

The differentiator between improvisation-under-uncertainty and a followed branch is exactly
the doctrine text under test — the explicit "substitute and record" clause and the named
`skills/workbench/templates/` fallback. Both arms reach the same *artifact* (README +
OVERVIEW substitution; STATE_NOTE authored from the workbench template), but the before-arm
reaches it as a self-flagged guess against an imperative that "does not license" it, while
the after-arm reaches it as a high-confidence sanctioned action. The escape-hatch text is
load-bearing for *legibility and confidence*, which is the cost the lesson records
("had to reason through ... unprompted"). This is the process-documentation analogue of a
passing regression test for the doctrine edit.

## Method notes (for the corpus)

- Both arms were run as throwaway subagents, same scenario and repo facts, imperative text
  the sole variable; neither knew its arm. Verbatim confidence self-ratings are the evidence.
- This lesson's cost is *improvisation / rediscovery*, not an outright wrong action — so the
  drill's PASS criterion is the collapse of self-rated uncertainty (low→high) and the
  disappearance of "invention required," not a crashed command. Honest-null was on the table:
  had the before-arm followed the same branch with high confidence and no "unlicensed
  improvisation" note, the fix would have been decorative and the disposition a defer/amend.
  It did not — the improvisation reproduced verbatim.
