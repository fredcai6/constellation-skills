## Wave review -- w6-generator

One issue merged: C2 (e4c80f85), plus G1 (2a22c00a) and C1 (0ab7ecab) landing alongside it. Suite on merged main: 2824 passed, 3 skipped, 1121 subtests. The corpus sweep held at exactly 23 fault lines throughout, which is what proves no shipped template was quietly moved to make the generator's output validate.

**The wave did what it set out to do.** `scripts/generate_spine.py` compiles a typed spec into an engine-native spine and calls `validate_spine.validate` as the literal last statement before writing -- any fault or undecidable entry refuses with nothing written. There is no raw-command field anywhere in the spec format: a check is authored as one of five typed kinds, never as a shell string typed from memory, which is the class of defect the generator exists to close. Role specs exist for the implementer and the reviewer, and one drove to a terminal state in a real dispatch.

**TDD got a supported form rather than a hole.** A pytest check may declare `not_yet_written`, and generation reports `undecidable-pytest-not-yet-written` rather than a fault. The obvious risk is that this becomes a general-purpose way to author a gate that cannot fail, so it was attacked directly: a gate whose only postcondition is such a declaration is refused by `falsifiable-all-null`, with nothing written.

**The finding that changes the plan is about review, not code.** This branch was reviewed five times. The first four each ran real commands and each answered its own questions correctly, and each missed something different: a field that was never quoted, a stale session id present on nine of nine gates, that same id written into a review's own evidence line as proof of completeness, and a divergence that one reviewer saw, described accurately, and then scoped away. The pattern is one sentence: a review establishes that a mechanism operates and does not ask whether the value it carries is right. Absence and ubiquity both read as correct. The fifth review broke it by treating its own green results as questions -- and found nine stale session ids nobody had looked for. That evidence belongs to #558.

**A definition-of-done item recorded as holding does not hold.** Agent-facing instruction still names the engine CLI in 11 shipped files -- 15 fallback clauses and 9 `<engine>` tokens, including all three orchestrator spine templates. Two of those clauses call the CLI the only path for an in-session dispatched crew, which wave 5 disproved by dispatching one. Wave 5's cleanup covered the crew-facing tier and the claim was carried forward without remeasurement. It is now a launched workstream.
