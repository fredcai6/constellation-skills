# Disposition — #596: `CONSTELLATION_FEEDBACK.md` is still mandated after the switch to the episode ledger

**Gate:** `g4-implement`, work id `567-d1`, lane D1.
**Disposition:** **reproduces, in a narrower and sharper form than the issue frames it — repaired in
three files.** The issue's sharpest claim is **confirmed**: the `commander-delegated` clause is false
as written. Its framing of the other sites needs one correction: `CONSTELLATION_FEEDBACK.md` was
never retired, so the defect is not "a retired file is still mandated" — it is that **three live
sites mandate collecting or staging an export that no gate any longer writes or checks**.

---

## 1. The crux, measured first: the `feedback` gate's real postconditions

`skills/commander/templates/COMMANDER_SPINE.template.json`, `feedback` gate, quoted verbatim:

```json
"postconditions": [{"id": "c1", "statement": "this run captured at least one episode: an episode in the store records this work id", "check": {"kind": "command", "command": "python <commander-skill-dir>/scripts/verify_episode_captured.py <work-id> --store-root episodes --phase feedback"}, "satisfied": false}],
```

One postcondition. One check. It runs `verify_episode_captured.py` and nothing else.

**Verdict on the issue's sharpest claim: the `commander-delegated` clause is FALSE as written.** The
clause said:

> A `FENCE.md` citation **without** the staged export still fails the gate — learning cannot be
> silently dropped.

No export, staged or unstaged, cited or uncited, can fail the `feedback` gate, because the gate never
looks at one. Nor can it fail `archive`: that gate's five postconditions are the tracked episode
(`c1`), commit-and-push (`c2`), an open-or-merged PR (`c2b`), the released lease (`c3`), and the
`git-change-policy` (`c4`) — and `c4` **deny-globs** `.agent-work/CONSTELLATION_FEEDBACK.md`, so the
one place the export meets a gate at all, the gate refuses to let it into the commit.

The clause taught the exact opposite of what runs, which is why the 2026-08-15 lane obeyed it. It is
worse than a redundant mandate: an agent that believes the gate checks the export will produce one,
and an Admiral that believes the same will harvest it.

## 5. The two questions the handoff required answers to

**Q1 — does the staging step still have a job?** **Yes, but only when the run produced an export.**
The fence case that motivated staging is real and unchanged: a Commander forbidden from writing the
main checkout cannot write to the durable `.agent-work/` root. What changed is that its *episodes*
no longer need staging at all — `episodes/` is tracked inside the worktree and the commit carries
them out, which is exactly what the delegated skill already said. So staging's remaining job is the
export alone, and since no gate writes an export, the honest instruction is conditional: stage it if
you wrote one; if you did not, stage nothing. The alternative — deleting staging outright — would
strand a genuinely fenced run that *does* write one, e.g. a Commander running in a consuming project
where the cross-project channel is live (§6).

**Q2 — is the `archive` `c4` deny-glob still consistent?** **Yes, and it was the strongest evidence
against the old wording.** `c4` deny-globs `.agent-work/CONSTELLATION_FEEDBACK.md` and its
`.collected.json` sidecar, i.e. the run is refused closeout if it tries to *commit* the export into
this repo. That is the opposite of a mandate, and it was already true while three sites said the
export was required. My change touches neither `c4` nor the staging path: the staged location
`.agent-work/staged-feedback/<work-id>/` is not in `deny_globs`, and `.agent-work/**` is in
`allow_globs`, so staging remains permitted and committing the durable-root export remains refused.
No edit to `COMMANDER_SPINE.template.json`, so its `.agent-work/templates/` and `.baseline/` mirrors
need no sweep.

## 6. The two scripts: deliberately out of scope, and why

`scripts/collect_feedback.py` and `scripts/agent_work_root.py` are in this lane's sole-writer list.
**Neither is changed.**

- **`collect_feedback.py` is not a mandate, it is a live tool with a live caller.** It sweeps
  *consuming projects'* exports (`docs/DEBT_SWEEP_CADENCE.md` names the roots and the exact
  invocation; `skills/admiral/SKILL.md:94` runs it at epic closeout when the epic is against this
  repo). The channel it serves is cross-project — a Commander in `story_time` recording that a
  *skill* was wrong — which the episode store does not replace: `episodes/` is per-repo and this
  repo cannot read another project's. Removing its capability would make the grep clean and break
  the only cross-project path, which the handoff forbids in as many words.
- **`agent_work_root.py:4` is a docstring describing which artifacts the durable root holds.** It
  describes; it does not instruct. Nothing about the episode ledger makes the description false.

The issue is about the mandate. Both scripts support the file without mandating it, so neither is in
scope. Stated deliberately, as the handoff required.
