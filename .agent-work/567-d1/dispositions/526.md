## 3. Defect 2: the survey-reuse convention — reproduces

The Commander's preliminary measurement is **confirmed**. `skills/reviewer/SKILL.md:30` documents the
consolidation guard and the `--override-reason` asymmetry well:

> `consolidate` refuses APPROVE while any check is recorded `fail` **unless you supply
> `--override-reason`** ... a real finding has exactly two honest exits ... Never downgrade a `fail`
> to `pass` to get APPROVE through.

And the negative — nothing in the corpus says what to do with a survey that already exists:

```
$ grep -rniE 'second round|re-review|previous round|round 2|existing survey|reuse the survey' skills/reviewer/
(no output)
```

The only adjacent instruction is `skills/reviewer/SKILL.md:26`, which names one hard-coded path —
*"create the checklist at the path the handoff gives (`.agent-work/<work-id>/<gate>-review/review.json`)"*
— i.e. exactly the file a second round collides with. Written down nowhere, as the issue says.

**This lane's own two-round review is the evidence, and it decides the shape.** Gate `g1b` was
reviewed twice:

```
$ .agent-work/567-d1/g1b-review/review.json     BLOCK  10 items  r4-quality: fail, r7-attack: fail
$ .agent-work/567-d1/g1b-review/review-2.json   APPROVE 12 items  all pass, override_reason: none
```

**Which of the two shapes this run used: a new round file**, `review-2.json`, with round 1 preserved
untouched, and five rechecks appended into the new file as flat siblings (`r7-oracle`, `r8-cost`,
`r9-regression`, `r10-import`, `r11-attack`) on top of the template's base checks.

**And the evidence shows why the other shape is wrong**, which is the part worth writing down. Had
round 2 re-driven `review.json`, `r4-quality` and `r7-attack` were already recorded `fail`, so APPROVE
had exactly two routes out of that file: re-record a `fail` as `pass` — the downgrade SKILL.md:30
forbids in as many words — or `--override-reason`, which that same paragraph reserves for *a finding
that does not bar the change*, not one that was fixed. Either way round 1's BLOCK stops being
legible. The new-file shape needed neither: `review-2.json` consolidated APPROVE with
`override_reason: none`, and round 1's two `fail`s are still readable in full.

**Fix.** One paragraph added to `skills/reviewer/SKILL.md`, directly after the consolidation-guard
paragraph it depends on. **Before:** nothing — the paragraph is new; the preceding text is unchanged.
**After:**

> **On a re-review, open a new round file; never re-drive the previous round's survey.** A gate sent
> back for rework already has a consolidated survey, and its recorded `fail`s are the record of why it
> was sent back. Getting APPROVE out of that same file needs either a `fail` re-recorded as `pass` —
> the downgrade forbidden above — or an `--override-reason` written for a finding that was *fixed*
> rather than one that does not bar the change; both bury the round that blocked. So keep each round
> in its own file beside the last, numbered at the Survey State Location the handoff gives
> (`review.json`, then `review-2.json`, ...), leave the earlier files untouched as the audit record,
> and build the new round from the template's base checks. Add this round's rechecks with `append`,
> one flat sibling per finding the previous round raised — `append` takes the NEW check's own id and
> refuses an id that already exists, so a recheck is a sibling, never a child of the check it re-runs.
> Consolidate the new file on its own evidence.

The `append`-is-a-sibling sentence is not decoration: the engine reference states it explicitly
(*"`<id>` is the NEW leaf's own id, a flat sibling, NOT an anchor id to nest a check under an existing
item; anchoring under an existing id is refused as 'already exists'"*), and it is the one mechanical
fact a reviewer needs to carry out the convention without a refusal.

The issue's own guess at the convention — *append a recheck item as a sibling, record it,
**re-consolidate with `--override-reason`*** — is half right. The append-as-sibling half is what this
run did and is written down; the re-consolidate-with-override half is the move the evidence argues
against, so it is written down as the thing **not** to do, with the reason.
