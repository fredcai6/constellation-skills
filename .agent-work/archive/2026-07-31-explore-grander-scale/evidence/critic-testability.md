# Critic findings — lens: testability

Cold read of `DESIGN_SPEC.md` only. Disposition and Reason left empty by design; the critic does not self-triage.

| ID | Lens | Severity | Finding | Disposition | Reason |
|---|---|---|---|---|---|
| T1 | testability | BLOCKING | The projection manifest is designated as "the map-use observability instrument" (B2, B3), but a manifest is a byproduct of assembly — it records what was *delivered into* context, not what the agent *used*. An agent handed a map section and ignoring it produces the same manifest as one that oriented from it. The spec's own Scout audit finding is that "orchestrator map consumption is attested rather than observed"; the chosen instrument measures delivery, so the tracer reproduces exactly the gap it was commissioned to close. B3's success criterion ("agents use high-level architecture connections to orient before inspecting targeted code") is not observable from the instrument named to observe it. | | |
| T2 | testability | BLOCKING | The B3 falsification condition — "seams are consistently found by code crawling with map anchors backfilled afterward" — requires an interleaved ordering record of map loads against ad-hoc source reads. The manifest as specified covers deterministic assembly only; unplanned source reads during a run are tool calls, not assembly events, so nothing in the design timestamps them relative to map loads. Out of scope then forecloses the fix: "success/clean-use telemetry beyond mechanism byproducts" must "earn its way in via a specific question." The tracer's primary falsifier therefore depends on evidence the design does not capture and has pre-ruled out capturing. | | |
| T3 | testability | BLOCKING | B2's actual architectural risk is untested. The spec calls kernel-plus-just-in-time-fragments "a deliberate architectural break" from one large skill per role, resting on two load-bearing claims: that a slim kernel plus late-loaded fragments is sufficient for a role to do its job, and that "run artifacts carry accumulated state between steps, so late loading never means lost understanding." The only B2 pathway tests projection determinism. A byte-identical projection can be byte-identically insufficient. Determinism is a proxy for reproducibility, not for adequacy; the break could ship, degrade every role's competence, and pass its stated test. | | |
| T4 | testability | BLOCKING | The tripwired-deletion pathway is unfalsifiable as written. Its falsifier is "a regression traceable to the deletion occurs and the tripwire never surfaces it or never connects it back to the removal" — which can only be observed by some channel that independently knows a regression occurred and traces to the deletion. That is precisely the knowledge the tripwire exists to supply, and no independent oracle is specified. A silent regression the tripwire misses is indistinguishable from clean success, so the test can only ever return "pass." Given "pre-learning makes deletion safe" is the standing pressure against instruction growth, its central mechanism has no failing state. | | |
| T5 | testability | BLOCKING | B4 (deterministic context queries) has no testing pathway at all. It defines four named queries, a bounded-working-set assembly procedure, and a show-your-work obligation (connections followed, source per item, exclusions with reason, broken links) — every one of which is concretely checkable, and none of which is exercised or falsifiable anywhere in Testing pathways. B4 sits in Stratum B, which the spec states "is what gets cut," so an entire cuttable element can be built and declared done against no evidence. | | |
| T6 | testability | BLOCKING | B0.2 — "no stochastic step in the load path," named as the forbidden move — has no pathway, and B4 appears to violate it in a way no test would catch. B4 permits "an LLM may help translate a vague request into one of these named queries." Query selection determines what gets loaded, so a stochastic step sits at the entrance to the load path even though the selected query runs mechanically. Rebuilding a projection twice from a fixed recipe cannot detect this, because it holds the recipe fixed. Nothing checks the recipe-selection boundary, which is where the rule can actually be broken. | | |
| T7 | testability | MAJOR | B3's degraded mode has no pathway. "A missing, stale, or contradictory map produces a reported degraded mode ... never a silent fallback to full code crawling" is the safety valve of the whole tracer and is cheap to exercise (remove the entrypoint, staleness-stamp it, contradict it, run a task, confirm the report). Its absence means the failure mode the design most fears — silent fallback — is the one condition never deliberately induced. | | |
| T8 | testability | MAJOR | The B3 correctness claim has no control arm. "Regress correctness" and "targeted verification stayed correct" are comparative claims with no baseline capture specified: no pre-change run of the same representative tasks, no non-map-first condition, no recorded correctness measure. Combined with a success criterion the spec marks "human-owned," the verdict reduces to a retrospective judgment call over runs that were never paired against anything. | | |
| T9 | testability | MAJOR | Every B1 pathway is a single-instance exercise: "one real simplification," "one Curator dispatch," "a run that hits a refusal/reopen." These mechanisms make aggregate claims (standing pressure against growth, rhymes findable across runs, corpus coherence), and N=1 cannot falsify an aggregate. The deletion is additionally self-selected by the same party filing its tripwire, biasing toward removals whose failure mode is easy to predict — the easy case for the mechanism, not a test of it. | | |
| T10 | testability | MAJOR | The determinism test is weaker than the risk. "Rebuilding any projection twice from the same canonical revision" will pass for anything short of an explicit shuffle when run back-to-back in one environment. The real irreproducibility sources are cross-environment: filesystem enumeration order, dict/set ordering, locale and collation, line endings and path separators (this corpus is developed on Windows), and embedded clock or run identifiers. The pathway should require a rebuild from a clean checkout in a different environment before claiming determinism. | | |
| T11 | testability | MAJOR | "Silent divergence between canon and projection" is listed as a falsifier for B2 but no pathway can detect it. Rebuilding twice compares a projection to itself; it says nothing about whether the projection committed in git still matches what the current canon would generate. Detecting staleness requires a drift check — regenerate and diff against the committed artifact, failing if they differ — which is never specified as a mechanism, a hook, or a step. Under the spec's own two-bin rule this is a catastrophic-class invariant (agents silently loading stale doctrine) left as an unowned aspiration. | | |
| T12 | testability | MAJOR | The episode-capture pathway cannot observe its own claim. "Carries the mechanical fields without agent effort" and "falsified if episode writing depends on agent diligence" require a negative control — a run where the agent does not attempt to write the record, or where the write path is severed — and none is specified. An observed agent will fill the fields, so a passing observation is consistent with total dependence on diligence. | | |
| T13 | testability | MAJOR | B1 never partitions the episode record into mechanically-captured versus agent-supplied fields, so the pathway's pass criterion is undefined. The list spans work-id, active gate, refusals, reopens (plainly mechanical) and task intent, expected behavior, observed behavior, impact/cost, workaround (plainly not). "Much of this is mechanically capturable" is unfalsifiable until "much" is enumerated field by field; as written, any result can be argued to satisfy it. | | |
| T14 | testability | MAJOR | The durability claim that justifies replacing the current inbox — "the structured episode outlives its consolidation, so rhymes remain findable across runs" — has no pathway. Episode capture tests one write in one run; nothing tests retrieval across runs, across projects, or after a consolidation has occurred. This is the specific defect being fixed (evaporate-after-graduation), it is cheap to exercise by seeding episodes and querying, and it is the one B1 property with no test. | | |
| T15 | testability | MAJOR | The Curator coherence-sweep pathway tests containment rather than capability. Its falsifiers — findings mutating doctrine directly, findings arriving unattributable — check that the sweep stays in its lane; nothing checks that it finds anything true. A sweep returning zero findings, or two hundred worthless ones, passes as specified. A seeded-defect check (plant known incoherences in the bounded slice, measure how many surface and at what noise ratio) is the obvious falsification of "hunt incoherence" and is absent. | | |
| T16 | testability | MAJOR | The two-bin routing pathway tests paperwork, not the rule. Requiring each cluster to "state its bin and, for prose, its tripwire" verifies a field is filled, not that the routing decision is correct; a cluster that cannot afford to fail once, filed as prose with a tripwire, passes cleanly. The only check that touches the actual rule — the inventory pass over existing catastrophic-class invariants — is "deferred to a later drill" with no trigger, owner, or deadline, so B0.4 ships with no active pathway. | | |
| T17 | testability | MAJOR | No pathway names a verdict owner, a sample size, a threshold, or a timebox, so none can conclude. "Consistently found by code crawling," "regress correctness," and "representative tasks" all lack a decision procedure, and there is no statement of what happens on falsification (revert, rework, escalate). B3 compounds this: "Deferred: corpus choice is the first implementing decision" means the tracer's only measurement cannot be scheduled, costed, or even scoped at cut time. | | |
| T18 | testability | MAJOR | The design-it-twice obligation is transferred with no verification that it lands. "Each implementing issue for these three interfaces must run design-it-twice before fixing a schema" is an unenforced instruction: no gate, no checklist item, no artifact required, and no tripwire under the spec's own B0.4 test. The three interfaces are named load-bearing, meaning we cannot afford to observe this failing once — which by the spec's own rule makes it mechanization-class, yet it is filed as prose with nothing owning it. | | |
| T19 | testability | MAJOR | The outcome B1 actually claims — "the standing pressure against instruction growth" — is never measured, though it is the cheapest measurable thing in the spec. Corpus size, per-role kernel size, and doctrine file count over time are all recoverable from git with no new infrastructure. Without a trend measurement, the accrete-then-consolidate loop can run indefinitely while the corpus grows monotonically and every individual pathway still passes. | | |
| T20 | testability | MAJOR | The Confirmation block requires "Assumptions exercised" and "Assumptions accepted untested," but the spec contains no assumption inventory to draw them from. Testing pathways is organized by design element, not by assumption, and the exploration digest marks its findings "NOT runtime-verified," "NOT installed," "documentation comparison only," "simulated single-environment evidence" without carrying them forward into a list. The confirm gate's two most consequential fields can be filled with anything, and nothing downstream can check them. | | |
| T21 | testability | MINOR | The byte-identical criterion is undefined for fields that legitimately vary. The manifest must record "what and from which revision," and any run identifier, generation timestamp, or absolute path embedded in a projection or manifest breaks byte-identity for reasons unrelated to determinism. The pathway does not separate the projection artifact from the manifest or name an exclusion set, so the first legitimate variance will read as a failure and get waived, decaying the check. | | |
| T22 | testability | MINOR | "Every Stratum B element must be buildable without committing to any Stratum A implementation, and must not foreclose it" is a per-element obligation with no verification step, reviewer, or checklist. Foreclosure is discovered late and expensively by nature; without a named check at cut or review time, the constraint is aspirational, and the spec's core structural device (strata that orient without binding) has no way to be found violated. | | |
| T23 | testability | MINOR | B0.5's floor — "nothing that changes how anything works lands wholly unreviewed" — has no pathway despite being mechanically checkable against git history (every doctrine-affecting commit carrying an attached review artifact). It is stated as "the standing floor, not a fallback," which is the strength of claim that ordinarily earns a mechanism under the spec's own two-bin rule. | | |
| T24 | testability | MINOR | The spec asserts a mechanical backstop it never exercises: `verify_spec_confirmed.py` "refuses it until the Confirmation block below is filled" and every Disposition cell is filled. Nothing tests that the refusal fails closed — that a partially-filled block, a present-but-empty Disposition cell, or a deleted marker line with Status still DRAFT is actually rejected. A gate claimed as the backstop for the confirm decision should have a test that it refuses. | | |
| T25 | testability | MINOR | B4's entry condition is unobservable. It is scoped as an "earned increment, after B2/B3," but nothing states what B3 must demonstrate to earn it — no threshold on map-first behavior, no minimum run count, no owner of the call. As written the gate is satisfied by B2 and B3 merely existing, so the sequencing constraint cannot be found violated. | | |
