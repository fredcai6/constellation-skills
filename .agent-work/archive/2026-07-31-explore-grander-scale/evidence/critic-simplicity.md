# Critic findings — lens: simplicity/YAGNI (what can be deleted)

Cold read of `DESIGN_SPEC.md` only. Disposition and Reason left empty by design — the critic does not self-triage.

| ID | Lens | Severity | Finding | Disposition | Reason |
|---|---|---|---|---|---|
| S1 | simplicity | BLOCKING | The spec's own definition of "done" (Intent) is two things: a map-first support system whose use is observable, and a reworked lessons framework. Stratum B contains four sections, and the two largest commitments — B2's monolith-to-kernel-plus-fragments re-architecture and B4's context queries — appear in neither half of that sentence. Stratum B is declared "what gets cut," so a to-issues agent reading this document cannot tell whether it is cutting two deliverables or four. Either "done" is wrong or B2/B4 do not belong in the cut stratum. This must be resolved before any issue set exists, because it decides roughly two-thirds of the work. | | |
| S2 | simplicity | BLOCKING | B2 commits to the single largest structural change in the spec — splitting every role skill into an always-loaded kernel plus just-in-time fragments — on one asserted premise: "every correction has historically made it larger." No size measurement, no failure attributable to skill size, no threshold at which the current shape stops working. Meanwhile this same spec contains a strictly cheaper intervention aimed at the identical problem: tripwired deletion (B1) plus the two-bin rule (B0.4), which shrink the corpus without touching how anything loads. The spec never compares them. The simpler path is to run deletion first and re-architect only if deletion demonstrably cannot get the kernel small enough. A spec that declares itself anti-accretion should not adopt its most expensive mechanism on an unmeasured premise. | | |
| S3 | simplicity | MAJOR | B2 specifies two projection mechanisms where one would serve: ahead-of-time generation for slow-changing role doctrine, and per-run deterministic assembly for task working sets. Both are deterministic assembly from canonical Markdown keyed by a role or spine node. The only stated justification for the ahead-of-time path is that a diff exists in git — but per-run assembly can write its output to a tracked path on any cadence and produce the same diff. Two mechanisms means two code paths, two determinism guarantees, two sets of failure modes, and a permanent question at every doctrine change about which path owns it. | | |
| S4 | simplicity | MAJOR | B4's four named queries are not four procedures. "Orient to a capability" is already specified to return the constraints that govern it and where its behavior is verified — which is precisely what "find governing policy" and "find verification surfaces" return. All four are one traversal from a named anchor with a filter on which connection types to follow. Collapsing them to a single parameterized recipe removes three surfaces to build, document, and keep coherent. The spec resists this only by insisting these are "named recipes, not a general query language," but the boundary it is defending is a naming convention, not an architectural one — a fixed procedure taking a type filter is not a query language. | | |
| S5 | simplicity | MAJOR | Stratum A does no work in this document. The spec states that every Stratum B element must be buildable without committing to any Stratum A implementation and must not foreclose it. It then never names one concrete constraint Stratum A places on Stratum B that B0's five principles do not already impose. Its stated function — "it orients and constrains what is built now" — is unfalsifiable as written. Its cost is real: seven paragraphs of vocabulary (frames, assertions with weak/medium/strong, home frames, the idea commons, federation) sitting inside the document that gets cut into issues, inviting implementers to build toward it. Deleting Stratum A to a separate direction note leaves this spec purely actionable and loses nothing the spec can point at. | | |
| S6 | simplicity | MAJOR | The episode record specifies roughly a dozen fields before anything has been shown to need them. The stated purpose is narrow — make rhymes findable across runs — which needs little more than role plus spine step, expected versus observed, and a pointer to artifacts. Worse, the spec is internally inconsistent about them: "impact/cost" and "workaround" are human-judgment fields requiring agent effort, while the B1 testing pathway declares the design falsified if "episode writing depends on agent diligence." Fields that are neither mechanically capturable nor exercised by any named consumer should be cut until a consolidation attempt demonstrably fails without them. | | |
| S7 | simplicity | MAJOR | Removing the inbox's evaporate-after-graduation behavior adds unbounded growth with no retirement policy. The spec's own cited excursion finding names retirement as a required stage of the experience lifecycle, and B1 applies retirement to prose doctrine but drops it for the episode store entirely. A store that only grows, searched by an LLM looking for rhymes, degrades exactly the way the monolithic skills B2 complains about degrade — and it reintroduces a stochastic step at the discovery end of the pipeline that B0.2 works hard to eliminate at the load end. Either specify episode retirement or justify why this store is the one thing that may grow forever. | | |
| S8 | simplicity | MAJOR | The Curator adversarial-subagent panel is speculative machinery. Nothing in the tracer depends on it; real-run episodes already feed the observation store, and no evidence is offered that real runs will underflow and need synthetic observations generated. Its two defining parameters — which adversarial viewpoints and on what cadence — are listed in the spec's own open threads as unresolved. Committing to a mechanism whose configuration is unknown, whose input queue is not yet known to be empty, is the definition of building ahead of need. Delete it, run the store on real episodes, and add generation only if the store proves too sparse to find clusters. | | |
| S9 | simplicity | MAJOR | B3's degraded mode is specified over three trigger conditions — missing, stale, or contradictory map — of which only one is mechanically detectable. Staleness needs a freshness contract the spec does not define, and contradiction between map and code is the hard verification problem the whole map-first idea is trying to avoid doing. If those two are not mechanical, degraded mode collapses into an agent self-reporting its own confidence, which is a stochastic actuator and violates B0.1. Shrink the mechanism to what is checkable — the canonical entrypoint resolves or it does not — and drop the other two triggers until something can detect them. | | |
| S10 | simplicity | MAJOR | The manifest is claimed as a free byproduct requiring "no new watching infrastructure," but B3 asks it to answer whether the map found the seam before broad source crawling. That is not a list of what was loaded; it is an ordered trace interleaving map reads with source reads, which deterministic assembly does not produce on its own — assembly knows what it handed over, not what the agent read afterward or in what order. Either the B3 measurement question must weaken to something a load manifest can actually answer, or the spec must admit it is building an access trace and price it. As written, the cheapest-looking element of B3 is hiding its cost. | | |
| S11 | simplicity | MAJOR | B0.2 reads as a strong guarantee — no stochastic step between canonical truth and an agent's active surface — but the spec's own pipeline puts an LLM at the consolidation step, where it summarizes clusters of episodes into instruction changes that land in canon and then project deterministically into context. The stochastic summarization has been moved one hop upstream, not eliminated. The principle constrains only the last hop. Stating it plainly ("the assembly step is deterministic and attributable") is both true and shorter; the current phrasing will be read by implementers as a guarantee the system does not provide. | | |
| S12 | simplicity | MAJOR | B0.5 makes rigorous independent agentic review — cold reviewer, critic panel — the standing floor for anything that changes how anything works. That is the most expensive possible default, adopted with no evidence that unreviewed changes have caused problems on a single-author personal project, and it taxes most heavily the exact activity B1 depends on: cheap experimental deletions of prose doctrine. A deletion that needs a critic panel will not be attempted often enough to generate the observations the design needs. Scale the floor to consequence class, or the anti-accretion mechanism will be strangled by the review mechanism. | | |
| S13 | simplicity | MAJOR | The dependency story is inverted. B3 — the element the spec calls the high-value tracer — depends on nothing else in Stratum B. Its core is resolving one canonical map entrypoint in the Commander context step and deleting the scattered prose it supersedes; that is shippable now and immediately measurable. Yet it is presented third, after a corpus re-architecture, and B4 is gated on "after B2/B3" as though B2 were a prerequisite for map use. Nothing in B3 needs the kernel-plus-fragments split or the projection generator. Ordering B3 first and letting its measurement decide whether B2 is needed at all would let the spec test its central hypothesis before spending its largest budget. | | |
| S14 | simplicity | MAJOR | The two-bin rule (B0.4) is adopted as normative while the inventory that would show it is satisfiable is deferred. The rule states that anything that cannot afford to fail once is mechanized and its prose deleted because the mechanism owns it. Whether every catastrophic-class invariant in the current corpus can in fact be mechanized is exactly what the deferred "later drill" would find out. If some cannot, the rule has no bin for them and the corpus will accumulate prose that is neither prunable nor mechanized — an undeletable residue the rule does not acknowledge. Run the inventory before adopting the rule, or state the third bin. | | |
| S15 | simplicity | MAJOR | Three of the six testing pathways do not test the design. Projection determinism ("rebuild twice and diff, must be byte-identical") is a unit test of a pure function — it confirms the code works, not that deterministic projection was worth building. Two-bin routing ("each consolidated cluster must state its bin") is a compliance check that cannot fail in a way that teaches anything. Coherence sweep tests that a dispatch produces proposals, not that the proposals are worth having. Only map-first behavior and tripwired deletion are genuinely falsifiable. Cutting the other three removes work whose result is known in advance and sharpens what "exercised" means. | | |
| S16 | simplicity | MAJOR | The design imports institutional-scale process into a single-author project. Between an observation and an agent's active context there are five stages: episode capture, cluster consolidation, change classification, canonical corpus, projection. The excursions cited to justify this staging studied institutions and policy architectures, whose staging exists to survive many authors, turnover, and contested authority — none of which apply here. Each hop is a place work stalls and a place an implementer must build handoff machinery. The spec should name which stages exist because they are needed at this scale and collapse the rest; "it is a playground and complexity is the point" is a legitimate answer but must be stated, because it is in direct tension with the anti-accretion claim. | | |
| S17 | simplicity | MINOR | B0.1 and B0.2 are one principle stated twice. "Nothing stochastic is asked to produce a predictable result" is the general form; "no stochastic step in the load path" is that general form applied to its single application in this spec. Since no second application appears anywhere in Stratum B, the generalization earns nothing and doubles the surface a reader must reconcile. | | |
| S18 | simplicity | MINOR | One idea has three homes: the two-bin rule (B0.4), the mechanization-versus-instruction change classes (B1.2), and pre-learning with tripwires (B1.3) all say that a fix is either code or words, and that words are prunable under a filed prediction. Three statements of one idea in one document will drift apart under editing, and each will be cited independently as though it were a separate constraint. | | |
| S19 | simplicity | MINOR | The traversal recipe surface is listed as one of three load-bearing interfaces carrying a design-it-twice obligation, but its only consumer is B4, which the spec itself says must be earned by future evidence. Declaring an interface load-bearing before anything is known to bear on it commits an implementing issue to an expensive design ritual for a surface that may never be built. Drop it from the load-bearing list until B4 is earned; two load-bearing interfaces is a smaller and truer claim. | | |
| S20 | simplicity | MINOR | Assertion-strength has two homes and will drift. Stratum A specifies the weak/medium/strong truth model in some detail, while Out of scope says assertion-strength mechanics are preserved on the ideas board for a future exploration. The same deferred idea now exists in two places with different levels of detail and no stated relationship. One of them should be a pointer to the other. | | |
| S21 | simplicity | MINOR | The Confirmation block asserts a guarantee it then admits it cannot provide: it records a human decision while acknowledging the engine does not prove a human made the call. What actually holds is the loud marker line plus the downstream refusal to cut. The block's remaining fields — per-section approvals repeated for eleven sections, assumptions exercised, assumptions accepted untested — are ceremony over a mechanism that reduces to one marker and one script check. It could shrink to the marker, the disposition requirement, and a signature line without losing any enforcement. | | |
