## Intent

Cheap models under pressure take cheap exits — skip, theater, quit-early, fabrication, completion-theater-at-finish, wait-by-ending-turn. The #126→#129 arc measured that four flat-imperative wording clauses take one skill from ~1/3 to 3/3 strict terminal completion on sonnet; the #101 simplification review found the same protective force stripped from nine other skills into pointers that don't fire at load time. This pass designs ONE coherent counter-doctrine across the corpus, layered on three moments of the failure timeline:

- **Getting IN** — skill-text entry wording (S1 clamp restoration): no runtime channel reaches an agent before its first engine call.
- **Staying ON** — the engine rail (channel A): doctrine delivered by the engine's own responses at every decision point.
- **Not LEAVING** — the hook suite (channel B): the harness boundary refuses dishonest exits (turn-end mid-flight, post-compaction amnesia).

Also in-pass: the #134 fencing-aware staging fix (a mandatory-waive gate is a broken gate), and the S2 two-register resolution of morale doctrine. Done feels like: three measured arms (corpus-only / +rail / +rail+hooks) on the #129 harness, each arm's contribution visible, no skill relying on wording that was proven not to fire.

Kill condition (standing from #138): if the corpus-only arm alone hits target, the engine-side channels shrink to the cheapest defensible core.

## Chosen design

### D1. S1 — clamp restoration across the stripped skills

Stamp the proven four-clause shape — (1) engine-first entry, (2) solution-is-the-MIDDLE, (3) release-after-final-advance, (4) wait-loop — back into the corpus, transcription-grade (the measured wording, not a paraphrase). The target denominator is defined **by reference, not by count**: the stripped-skill enumeration in the #101 `SIMPLIFICATION_REVIEW.md` (the "nine" in earlier prose was a stale count; the review's list is authoritative, and the implementation issue enumerates it file-by-file). Ranked order:

1. crew implementer + crew reviewer (highest cheap-exit exposure),
2. `commander-core.md` (both commander modes inherit),
3. admiral + interrogator,
4. the six pointer-only skills get the **pointer-with-force** sentence.

**Pointer-with-force, final wording (flat register, imperative-carrying, one consequence clause):**

> Drive every step through the checklist engine and finish its sequence — final `advance`, then `release`, as journaled actions. Work the engine never saw did not happen. Full completion doctrine: `_shared/global-everyone.md`.

The imperative and the consequence live in the pointer itself; the shared file elaborates. This repairs the measured defect (bare pointers don't fire at load time) without re-inflating the six skills. **Accepted-untested (IF1):** the compressed pointer is unproven at the getting-IN moment — the 1/3→3/3 result was measured on the full four-clause shape. The exposure is bounded: the rail (D2) backstops everything from the first engine call onward, so the pointer alone owns only the pre-first-call window of the six lower-exposure skills. This rides into the Confirmation block's accepted-untested list. The review's judged-correct removals stay removed — no banner resurrection.

Design-it-twice: skipped as trivial for this sentence (stated reason: it is one sentence whose shape is dictated by the measured four-clause result plus x3's placement/wording findings; the load-bearing interface it points at gets the full treatment in D2).

### D2. Channel A — the engine rail (load-bearing interface; design-it-twice DONE, 3-way panel)

One function, `_rail(point, cl)`, in `checklist_engine.py`, appending a short doctrine block to the output of `claim`, `current`, `start`, `advance`, `attest`, `attach`, and REFUSED responses. `claim` is the agent's documented first engine call — railing it lands doctrine at the earliest reachable moment (IF5); `attest`/`attach` are the chokepoint where fabricated evidence for a claimed-pass step would be attached, so the check-failure/forbidden-exits doctrine rides there too (IF4). No new verbs, no schema change, no per-step authored text — gate tokens (position, distance-to-terminal, next imperative) derive from existing `items` state, **except the check-FAILURE point, which keys on the refusal code path itself** (the `EngineError` catch in `main()`), not on spine state: a failed advance leaves state identical to plain mid-flight, so the refusal event is the only deterministic trigger — and it is unit-testable by invoking a failing verb (TS1). Boundary definitions (TS2): *near-terminal* = the active step is the last step before release-eligibility; *terminal* = only `release` remains. The "why" is a fixed string keyed to decision-point *type*, five strings total, single table:

| Decision point | Rail string (flat, ends on the runnable next move) |
|---|---|
| early (entry/first steps) | "Work the engine never saw did not happen. Run the step's checks, then `attest` and `advance <id>`." |
| mid-flight | "A working solution is the MIDDLE of this run — you are N steps from done. Next: <imperative>. Run it." |
| check-FAILURE | "This check failed; that verdict is scoped to this check, not the approach. Do the missing work and `attest`/`attach` the evidence, or escalate with `block`/`waive` and a reason. Report 'this check failed', never 'this step is impossible'. Quiet abandonment and fabricated evidence are the two forbidden exits." |
| near-terminal | "The finish is a sequence, not an announcement. Final `advance` first, then `release` — the journal, not your prose, is the proof." |
| terminal | "Release is your last journaled action. Run `release`; do not claim it." |

Interface, deep-module terms: callers (skills, agents) learn nothing new — the rail rides the existing mandatory chokepoint of engine output. Invariants: rail text is deterministic from spine state or refusal path (unit-testable by substring); flat register enforced by the single string table (the enforcement half of morale doctrine has exactly one source, see D4); no rail on read-only verbs other than `current`. **Canonicality order (SY2):** the rail string table is the canonical enforcement source; the `global-everyone.md` scoped-nulls section is elaboration and cites the rail as canonical; the D1 clamps are the measured transcription, deliberately frozen (changing them re-opens the measurement, so they cannot silently drift). On conflict, the rail table wins. Honest nulls carried from the panel: the rail is deterrent-only, silent at turn-end and post-compaction — those are D3's decision points; it cannot fix #134 (that is D5).

Panel record (x1): A minimal-interface vs B hook-carried vs C conductor, compared on depth/locality/seam/testability + failure-shade coverage. Outcome: layered A+B hybrid ratified by the human 2026-07-12; C shelved shaped to issue #139. A per-gate authored "why" field was refused — it would relocate the nine-copies problem into the templates.

### D3. Channel B — the hook suite (design source: x1-designer-b)

One script, `scripts/hooks/spine_rail.py`, plus project `settings.json` wiring; three hook registrations (PreCompact was cut at review — a breadcrumb with no consumer is speculative abstraction by our own doctrine, SY6):

- **Stop** — refuses turn-end while a spine is mid-flight, judging *engine lease truth*, never agent claims. Escape hatch: a 3-strike no-progress nudge counter keyed on (journal-seq, active_id) — three consecutive refusals with no journal progress downgrade to a pass-through nudge, so a genuinely stuck agent is not trapped. Engine `block`/`waive` states are honored as honest stops.
- **SessionStart (compact | resume)** — re-injects the live `current` output (rail included), so post-compaction amnesia lands on the doctrine, not on a stale summary. The `source=compact` trigger is the one docs-only residual: live-probe it during implementation before trusting it in the measured arm.
- **PostToolUse on Bash** — maintains the session→spine binding by watching engine invocations; `release` deletes the binding, which is the suite's natural off-switch (no mid-flight spine, no hook opinions). Why this exists at all (SY7): its job is **discovery** — mapping *this session* to *its* spine file, which the Stop hook cannot cheaply derive (multiple work areas and concurrent sessions make a repo-wide spine scan ambiguous). It is not a second source of truth for mid-flight status: the Stop hook always reads lease/journal truth from the engine state file the binding points at.

Interface, deep-module terms: the hook suite re-encodes "what is terminal" in a second place (a named, accepted locality cost) and is Claude-Code-only (one-adapter portability debt, accepted). x2 resolved the channel's sharp dependency in favor: hooks fire in the eval's own headless mode, so this channel is measurable. The D2/D3 overlap at turn-end is kept for exactly one reason — **harness portability**: the rail's finish-sequence wording is the only turn-end/wait-loop counter on any harness without hooks (SY8). Stated honestly at the intent level (IF3): on a hookless harness, the wait-by-ending-turn and post-compaction exits are covered only by wording (rail + clamps), not by any refusal mechanism — an accepted scope limit of this pass, not a solved problem.

### D4. S2 — morale doctrine, two registers (human-ratified)

- **Enforcement half:** lives as the D2 rail string table — flat, at decision points, single source. Prose elaboration = an upgraded scoped-nulls section in `_shared/global-everyone.md`; skills carry pointers-with-force (D1). **No new morale file.**
- **Disposition half:** exploration-facing doctrine (explorer, prototyper, shotgun framing) gets a deliberate warm, joyful-optimistic register. Weakly evidenced (named honestly: the weakest-evidenced item in this stack, knowingly accepted) and also justified by maintainability — doctrine that is pleasant to inhabit gets maintained. Hard boundary: the warm register never enters rails, gates, or eval-adjacent text.

### D5. #134 — fencing-aware staging fix (small, in-pass)

Chosen shape (option 1 from the issue, vs. the rejected option 2 of a new fencing-aware engine verb — wider surface, new verb semantics, disproportionate to the defect): the `feedback`/`archive` gate conditions accept a **worktree-local staged trio** when a launch-order fence is in force. Concretely: the gate check passes if either (a) the canonical durable-root files were written, or (b) the worktree-local staging paths exist AND an evidence artifact attaches the staged path + a fence citation (launch-order reference). The Admiral's harvest-before-sweep substep remains the owner of the canonical write.

Invariant preserved (the issue's own): learning cannot be silently dropped — a fence citation without a staged trio still fails the gate; sweeping an unharvested worktree remains the named failure the closeout doctrine guards. What this deletes: the mandatory-waive, which was a broken gate.

Design-it-twice: skipped as trivial (stated reason: the issue itself enumerates exactly two candidate shapes; the comparison above is the record, and the conductor (#139) would dissolve the tension structurally later regardless).

### D6. Measurement plan

Three arms on the #129 harness, run **in parallel**, target ≤ half an hour wall-clock: **corpus-only** (D1 wording alone) / **+rail** (D1+D2) / **+rail+hooks** (D1+D2+D3). Run counts preregistered from the #136 methodology (TS5): **N=3 per arm for the diagnosis pass** (failure transcripts are the primary signal); **shrink/removal decisions require certification-grade evidence — N≥8 per arm**, accumulated rolling across same-corpus-hash runs (`CORPUS.json` id), never a single N=3 point comparison. "Adds nothing measurable" is defined as: no completion-rate gain **and** no shade-shift in the failure transcripts, at certification N. The +hooks arm requires a hooked-sandbox install (project settings.json present in the eval sandbox). Eval `task.md` prompts stay pure: zero test-awareness, zero workflow coaching (standing ruling).

Interpretation limits, stated up front: the arms are **nested**, so they answer the shipping question ("does adding this layer to what ships help?"), not the isolation question ("would this channel suffice alone") — a channel can be redundant-with-D1 without being ineffective in isolation, and removal decisions must say which claim they rest on (TS4). The SessionStart-compact re-injection is **unmeasured inside the +hooks arm** — no eval scenario forces a compaction, so the arm's result attributes nothing to that component; it ships on x2's probe evidence plus the implementation-time live probe of the trigger (TS6).

## Testing pathways

- **Rail (D2):** unit tests asserting rail substrings per decision-point type from constructed spine states, plus the check-FAILURE string asserted by invoking a failing verb and capturing the refusal output (the refusal-path trigger, TS1); behavioral effect via the +rail eval arm. Falsified if: +rail arm ≤ corpus-only arm on strict terminal completion at certification N (see D6's noise rule).
- **Hooks (D3):** unit-test the script's decision logic (stdin JSON → allow/refuse/nudge) including the 3-strike escape hatch; end-to-end via the +rail+hooks arm on the hooked sandbox. Falsified if: Stop-hook refusals trap a stuck agent (escape hatch fails) or the arm shows no reduction in turn-end/quit-early shades.
- **Clamp restoration (D1):** presence tests (transcription-grade wording present in the nine skills); behavioral effect via the corpus-only arm vs the #129 historical baseline.
- **#134 (D5):** engine unit test: fenced run with staged trio + fence-citation evidence → gate passes; fence citation without staged trio → gate refuses; unfenced run unchanged. The staged-trio fixture is built from the **actual worktree-local trio the #129–#131 delegated commander emitted at closeout** (the run that surfaced #134), not an invented shape (TS9). Field-falsified if a delegated commander still needs a waive to close out.
- **Durability (TS3, accepted-untested):** the premise that engine-delivered doctrine survives where skill wording erodes is NOT measurable by any arm this pass — the arms measure one-shot completion on a fresh snapshot. Durability is a structural argument (single canonical source at a mandatory chokepoint vs. copyable prose), recorded in the Confirmation block as an accepted-untested assumption; the honest future test is the next #101-style consolidation pass not stripping it.
- **Deferred to later drills:** the caps-vs-flat falsifiable prediction (optional arm, not this pass); per-skill eval scenarios (#136); behavioral measurement of post-compaction re-injection (needs a compaction-forcing scenario — not currently constructible on demand; the live probe of the trigger is the implementation-time gate).
