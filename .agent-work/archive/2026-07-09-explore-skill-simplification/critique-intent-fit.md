# Critique — intent-fit lens

Spec under review: `DESIGN_SPEC.md` (skill-simplification). Lens: does the design serve its stated intent — agents absorbing lean, single-sourced, invoker-tailored skills; maintainer patching doctrine once; a periodic consolidation lifecycle — without the new machinery recreating the accretion disease it treats.

## Findings table

| ID | Lens | Severity | Finding | Disposition | Reason |
|---|---|---|---|---|---|
| IF1 | intent-fit | MAJOR | Workstream F is titled "Entry-split for heavy both-invoked roles" but applies to **interrogator, which is one of the leanest skills in the corpus (490 words — below triage 526, prototyper 893, and far below the 2,580-word commander it is paired with).** Interrogator already handles both audiences cleanly in a single paragraph (`skills/interrogator/SKILL.md:16`, "Delegated context (no reachable human)"). Splitting a working 490-word skill into two entry SKILL.md files plus a joint core reference **adds surface area to something already lean and working** — the exact accretion the pass exists to reverse. F's "heavy" criterion does not select interrogator; only the x2 mis-tailoring flag does, and mis-tailoring is a register fix, not a heaviness problem. | | |
| IF2 | intent-fit | BLOCKING | The intent names a "periodic consolidation lifecycle" and "standing machinery to repeat this consolidation on a cadence" as a core outcome, but **the curator (C) has no cadence mechanism**: it is human-only, manual, and explicitly "never scheduled, never a code-change reaction, never agent-dispatched" (§C Trigger). The corpus accreted precisely because no one periodically consolidated. A manual tool with no trigger reproduces that failure mode exactly — it is as forgettable as the manual discipline that already lapsed. The "cadence" is aspirational; nothing in the design creates it. | | |
| IF3 | intent-fit | MAJOR | **Nothing validates the pass's central hypothesis — that leaner/single-sourced skills are actually better absorbed by agents.** The curator's `curate_corpus.py` measures leanness (a proxy), and the eval harness (E) measures functional correctness (a regression guard); neither measures absorption or performance. The one metric that would confirm intent — "real token-cost deltas per role before/after" — is demoted to "Deferred to later drills… nice-to-have evidence, not a gate" (§Testing pathways). The goal is asserted, then the only test of it is deprioritized. | | |
| IF4 | intent-fit | MAJOR | Single-sourcing (A) is justified partly on agent token cost — "every token of sediment is context they pay for on every run" (§Intent). But the destinations are `_shared/global-*.md` buckets that a role **reads at the checklist context-read step** (`skills/_shared/global-everyone.md:1-9`; installer bundles them into every skill's `references/`, `install_constellation.py:94-113`). Relocating always-read doctrine from inline SKILL.md into an always-read bundled reference **does not reduce per-run tokens — it relocates them.** The real, defensible wins of A are drift-elimination and maintainer single-source; the agent-token-cost framing is overstated and risks selling A on a benefit it does not deliver. | | |
| IF5 | intent-fit | MAJOR | The autonomous eval harness (E) is a large net-new subsystem (runner `run_skill_eval.py`, scenario schema, fixture repos, temp-install mechanics, an explicitly-deferred contract) whose stated purpose — a substitute signal for downstream failures that "do not flow back to this repo" — is **orthogonal to this pass's simplification intent.** It is a regression/observability epic bundled into a cleanup pass. It also cuts against the secondary intent ("maintainer patches doctrine once," less to maintain) by adding a permanent subsystem to maintain. The spec's own "tackle last / deferred to its own gate" hedging signals it does not belong in this pass's scope. | | |
| IF6 | intent-fit | MINOR | The intent names agents-that-load-skills as the **primary** beneficiary ("every token of sediment is context they pay for"). Of six workstreams, only A, B, D, and F touch what agents load; **C (curator) and E (eval harness) reduce zero agent-loaded tokens** — they are maintainer/CI tooling serving the tertiary "lifecycle" intent. Half the specified effort does not serve the stated primary beneficiary. This is a priority/scope mismatch worth making explicit before confirm, so C/E are weighed as lifecycle investments rather than smuggled in under the token-cost banner. | | |
| IF7 | intent-fit | MAJOR | The curator (C) bundles corpus line/word measurement + description lint + duplication clustering + in-place mends + triage routing + **eval-scenario portfolio review** (§C Portfolio duty) into one new skill. That is multiple responsibilities in a single module — the same layering/coupling the pass indicts in commander ("doctrine stated in up to three places"). The eval-portfolio duty in particular couples C to E, so the two new subsystems are entangled at birth. The new machinery risks becoming the next epicenter the *next* curator run has to untangle. | | |
| IF8 | intent-fit | MINOR | F and C **increase the skill count** (curator + commander-delegated + any future splits) while the intent wants a corpus "absorbable in a single pass." Every new sibling entry is another description the agent selection layer must scan, and minting sibling entry skills revives the risk the spec itself rejected under "pushy descriptions… suite siblings would steal triggers." A `constellation-commander-delegated` (agent-driven single issue) also risks overlapping `constellation-admiral` (the human's delegate that dispatches single-issue work), adding a confusable pair the design does not list among its named confusables. | | |

## Notes

- **IF1** — Word counts measured directly: `commander` 2,580, `explorer` 1,695, `admiral` 1,495, `docent` 1,110, `prototyper` 893, `triage` 526, `interrogator` 490, `reviewer` 446, `scout` 384, `cartographer` 365 (`wc -w` over each `skills/<x>/SKILL.md`). Interrogator sits in the lean majority the intent wants to preserve. Its dual-audience handling already exists as one paragraph — `skills/interrogator/SKILL.md:16` binds "your user" to the frozen launch order / delegate when no human is reachable, with the interactive reading in the same place. F would triple the file count to re-express what one working paragraph already does. Spec §F, §60 ("B13 superseded by F").

- **IF2** — Spec §C Trigger: "never scheduled, never a code-change reaction, never agent-dispatched (untaken road: a report-only delegated mode, revivable later)." Spec §Intent frames the outcome as "standing machinery (curator + eval harness) to repeat this consolidation on a cadence." The gap: cadence is named as an outcome but the only mechanism that could produce it (scheduling / a dispatched report mode) is the untaken road. Compare §Out of scope, which rejects "re-accretion prevention machinery" — fair — but cadence-triggering is not prevention; it is the thing the lifecycle intent explicitly promises, and it is absent.

- **IF3** — Spec §Testing pathways, final bullet: "Deferred to later drills: … measuring real token-cost deltas per role before/after (nice-to-have evidence, not a gate)." Spec §Intent, done-state: "every SKILL.md reads as one deliberately-written document absorbable in a single pass." Nothing in A–F measures absorbability or agent performance against the pre-pass baseline; the curator lint (§C Invariant #1) measures counts and lint signatures, and E measures answer-correct / tests-green / spine-complete (§E Runner). Both are proxies at best for "better absorbed."

- **IF4** — `skills/_shared/global-everyone.md:1-9` describes itself as inherited doctrine "bundled with the skill at install," and the installer copies each bucket into every target skill's `references/` (`install_constellation.py:94-113`, `SKILL_REFERENCE_BUNDLES`). The everyone-bucket is not progressively-disclosed/optional — it is the role's context-read material. So for always-read doctrine the agent's token load is roughly invariant under A; only genuinely-inline-and-now-pointer content that the role would *not* otherwise read saves tokens. The drift and maintainer benefits (§A "reconcile-then-cut"; §Intent "duplication-with-drift is how they follow stale wording") are real and sufficient justification — the token claim is the weak leg.

- **IF5** — Spec §E, including "tackle last," "Verdict is computed," and "The detailed runner contract … is deliberately deferred to its own design gate at execution." A cleanup/consolidation pass that ships an autonomous headless-agent eval framework is doing two unrelated jobs. Recommend surfacing whether E is in-scope for *this* pass at all or is a dependent follow-on epic.

- **IF6** — Workstream roles per §Chosen design opening: "A–D and F are consolidation of the existing corpus; E adds the standing test machinery" — and C is likewise net-new tooling. Neither C nor E changes any installed SKILL.md an agent loads at run time (curator edits happen when a human runs it; E runs in a temp target). The primary-beneficiary framing in §Intent therefore covers only ~two-thirds of the work.

- **IF7** — Spec §C enumerates the curator's duties: measure (Invariant #1), flag (Invariant #2), mend, route (Triage), and Portfolio duty over eval scenarios. That last duty is defined in terms of E's artifacts, coupling the two new subsystems. Contrast the disease the pass names in §Intent: commander as "a layering epicenter … doctrine stated in up to three places." A single skill owning measurement + mutation + routing + cross-subsystem portfolio curation is a candidate epicenter of the same kind.

- **IF8** — Spec §Cross-cutting rule 1 lists confusable pairs requiring exclusion clauses: "scout/cartographer, explorer/interrogator, admiral/commander, curator/scout+write-a-skill." A `constellation-commander-delegated` entry (§F) is an agent-driven single-issue runner; `admiral` is "the human's delegate" dispatching issues. The design does not list commander-delegated/admiral as a confusable pair despite both being agent-context orchestration entries. §Rejected approaches records "pushy descriptions (suite siblings would steal triggers)" as a rejected idea — minting more sibling entries reintroduces the selection-pressure that concern was about.
