# Critique — simplicity / YAGNI lens

## Findings table

| ID | Lens | Severity | Finding | Disposition | Reason |
|---|---|---|---|---|---|
| S1 | simplicity | MAJOR | A *simplification* pass ships two new standing subsystems — the curator skill (C) and the autonomous eval harness (E). The stated intent (consolidate accreted duplication, doctrine-once, timeless truth) is fully delivered by A/B/D/F alone. C and E are net-new machinery, not consolidation. Scope could roughly halve — ship A/B/D/F now, spin C and E into a separate spec — while retaining nearly all of the intent's value. | | |
| S2 | simplicity | MAJOR | C and E justify each other circularly, so neither has a standalone forcing function in this pass. Curator's "portfolio duty" (§C) exists to review and propose *eval scenarios*; the eval harness's portfolio (§E) is "curator curates growth and mix over time." Remove both and nothing in A/B/D/F breaks; keep only one and half its stated purpose evaporates. Two subsystems co-defined into existence is the YAGNI signature. | | |
| S3 | simplicity | MAJOR | Ironic net-complexity increase for a cleanup spec. Adds: `constellation-curator` SKILL.md, `scripts/curate_corpus.py`, `curator-baseline.json`, `CURATOR_REPORT.md`, a golden-fixture test, `evals/` + scenarios, `scripts/run_skill_eval.py`, 2 net-new entry skills + 2 core references (F), and invoker-tag metadata across 14 skills. Deletes: `manifest.json`, one junk file, some banners — plus token-shrinking dedup that removes **zero files**. By file/subsystem/surface count the spec adds materially more than it removes. | | |
| S4 | simplicity | MAJOR | The interrogator entry-split (F) is unjustified. Splitting a 490-word skill into three files (two entries + a joint core) is pure complexity addition. Interrogator's actual issue (x2's human-prose/agent-loaded mis-tailoring) is a one-file rewrite, not a split. | | |

The generalized apparatus F builds — the mode-neutral "principal" device, the entry-only-over-joint-core pattern, the `-delegated` sibling with mirrored exclusion clauses — is then speculative abstraction erected for one skill. A one-off needs no generalized pattern: commander could keep a single skill with a short delegated-mode section, or two flat skills, without the core-reference indirection. | | |

| S7 | simplicity | MINOR | `curator-baseline.json` (the `--baseline` drift anchor) is speculative for a human-run periodic tool that already emits a full findings table — the table is the signal; a stored prior-run JSON to diff against is extra state a manual cadence doesn't need. The spec even concedes the first run has no baseline and just "seeds the convention." Drop the baseline until a second run proves the diff is actually wanted. | | |
| S8 | simplicity | MINOR | Invoker tags (human/agent/both in frontmatter) add metadata whose only consumer is the curator that also lints for its absence — self-referential. The convention plus its lint plus the "first run flags all 14 skills for missing tags" churn is machinery justified only by the machinery introducing it. | | |
| S9 | simplicity | MINOR | The eval harness is the maximal design where a minimal one existed. Computed-verdict, temp-install to a fresh target, headless fresh-agent launch (§E) is substantial infrastructure; the spec explicitly rejected the simpler human-read-transcript option. For a pass whose banner value is *simplification*, building an autonomous runner is the heaviest available choice. A handful of manual scenario checklists would deliver the same "does the cleaned corpus still work" signal at a fraction of the surface, and E is deferrable in full. | | |

Simpler path: do the cleanup; build the linter only if a later manual re-run proves tedious enough to automate. | | |

## Notes

- **S1** — Intent (§Intent, lines 18–22) frames the pass as "periodic preventive maintenance" to "consolidate what accreted." A/B (dedup + diets), D (hygiene), and F (entry-split) are all consolidation of existing corpus. C (§69–82) and E (§88–98) are the only additive-machinery workstreams; the spec's own sequencing note (line 37) puts E "last (human decision)" and C after everything, confirming both are separable from the consolidation core. The "done feels like" clause (line 22) smuggles "standing machinery (curator + eval harness)" into the definition of done — that is the scope inflation, not a requirement the intent forces.

- **S2** — §C "Portfolio duty" (line 78): the curator report "reviews eval-scenario coverage… and proposes new ones." §E "Portfolio" (line 94): "curator curates growth and mix over time." Each subsystem's justification points at the other. Neither is load-bearing for A/B/D/F.

- **S3** — Adds enumerated from §C (skill + `curate_corpus.py` + `curator-baseline.json` + `CURATOR_REPORT.md`, line 79), §Testing (golden-fixture test, line 124), §E (`evals/<name>/`, `scripts/run_skill_eval.py`, line 92–93), §F (commander→2 skills + core; interrogator→2 skills + core, line 102–105), §cross-cutting rule 4 (invoker tags on every skill, line 116). Deletes enumerated from §D (line 86). Dedup (§A) reduces token weight but the carrier files all remain with pointer lines (line 56).

- **S4** — Word counts measured in-repo: `wc -w` over each `skills/*/SKILL.md` gives commander 2580, interrogator 490, triage 526, prototyper 893. F (line 100, 107) splits commander + interrogator but leaves triage/prototyper (both heavier than interrogator) as one-line notes — an internal inconsistency in the "heavy" threshold. x2's mis-tailoring flag on interrogator (§Exploration record, line 29) is a register/audience rewrite, orthogonal to a structural split.

- **S5** — §F (line 104) introduces "the mode's binding of *the principal*" and a `constellation-commander-delegated` sibling. §F design-it-twice record (line 109) shows four candidates compared — but if commander is the sole real instance, the comparison was over-invested for a single-use pattern.

- **S6** — Rejection stated at §Intent (line 22, "accrete-then-consolidate, not prevention") and §Out of scope (line 133, "Any re-accretion prevention machinery — explicitly rejected"). Curator's mend/flag scope (§C invariant 1 and Mend, lines 74–76) includes "boilerplate that re-accreted since last run" and `--baseline` drift — cadence-based detection is prevention's twin.

- **S7** — §C Outputs (line 79): `curator-baseline.json` as "next run's diff anchor." §C error modes (line 80): "first run flags all skills… (expected; it seeds the convention)" — confirms the first-run baseline is empty and the drift feature is dormant until run 2.

- **S8** — Verified interrogator frontmatter carries no invoker tag (`skills/interrogator/SKILL.md` head). `SKILL_REFERENCE_BUNDLES` (install_constellation.py:98–113) is the actual audience-routing mechanism and keys on skill name, not on any human/agent/both tag. Nothing in `scripts/` reads an invoker tag.

- **S9** — §E interface (lines 90–96) specifies temp-install, one fresh headless agent, computed verdict, kept transcript. §E design-it-twice note (line 98) records human-read-transcript and skill-vs-repo-tool were the rejected simpler shapes. "Why autonomous" (line 96) rests on f1brainz signal not flowing back — a real gap, but it justifies *some* eval, not the maximal autonomous runner in this pass.

- **S10** — §C invariant 1 (line 74) lists the curator's checks; each maps to an A–D remediation (description discipline → cross-cutting rule 1; TOC → rule 3; duplication → cluster A; banners → cluster A "FOLLOW THIS SKILL STRICTLY" deletion). `manifest.json` confirmed dead (grep finds references only in `.agent-work/` exploration docs, not in any `scripts/*.py`), supporting D's delete — but that same evidence shows the standing linter has little live corpus to guard once A–D land.
