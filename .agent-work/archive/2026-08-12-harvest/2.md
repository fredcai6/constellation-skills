**Surfaced by the constellation feedback harvest (2026-06-24).** Agent-tool `isolation:"worktree"` did **not** create per-agent git worktrees on Windows — parallel commanders/subagents shared the single checkout and collided. Two **independent** projects hit this.

### Occurrences
- **network_elo** `worktree-isolation-not-real-on-windows` — two Commanders launched in one turn both operated in the shared checkout; one left staged-only work, the other pushed (near-race).
- **story_time** `worktree-isolation-not-guaranteed` — three parallel subagents shared the main checkout and collided on `git checkout -b` (one commit landed on a sibling's branch).

### Cost
Any Admiral run relying on `isolation: worktree` for parallel dispatch on Windows will collide — a real correctness / data-loss risk, not just friction.

### Proposed fix
Before any parallel dispatch, **VERIFY** isolation is real (`git worktree list` should show N>1 distinct paths after launch). If unverified — especially Windows / shared-checkout — treat isolation as **ABSENT** and default to **sequential dispatch**. Add a LAUNCH_ORDER / latitude pre-ruling field: `worktree isolation verified: yes/no — if no, sequential required`.
