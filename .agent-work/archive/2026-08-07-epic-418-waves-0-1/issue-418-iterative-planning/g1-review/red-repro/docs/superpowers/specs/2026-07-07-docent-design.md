# constellation-docent: human-facing explainer website from Cartographer truth

Status: design for build · 2026-07-07 · issue #61 · epic 20260706-dogfood-audit wave 4

## Context

The Constellation map is written for agents. Cartographer keeps `docs/architecture/` current: an
`index.md` (often a long chronological ledger of "Reconciled …" entries), one packet per subsystem,
sparse overlays (capabilities/constraints/purposes/decisions), and decision records. This is precise
and planning-authoritative, but it is not something a **human** can comfortably *explore* — f1Brainz's
`index.md` alone is 937 lines of dense reconcile prose.

User feedback (2026-07-06): "the architecture docs are solid for agents; we need something prettier for
humans to explore the codebase." This skill turns the same map truth into a navigable static website.

**Ratified direction** (human, 2026-07-07 checkpoint): a new skill `constellation-docent` that generates
a self-contained static HTML explainer under `docs/explainer/`, stamped with the source-map digest so a
stale pretty site is visibly flagged, demonstrated on one real project. Freshness is the load-bearing
constraint — *a stale pretty site is worse than none*.

The audience is the project's own human first — an explorer, not a marketing visitor. Visual bar:
readable, restrained, dark/light aware. A docs artifact, not a product landing page.

## Decisions

1. **Stack: single self-contained static folder, no build step, no network.** Output is plain `.html`
   files with **inline** CSS and JS — no CDN, no external fonts, no remote images, no fetch/XHR. The
   site opens from `file://` and survives an offline/CSP-locked environment. Rationale: it is a docs
   artifact committed into the repo and browsed locally; a build toolchain or SPA framework would add a
   dependency and a staleness surface for zero explorer benefit. Multiple pages linked by **relative**
   paths are fine (and preferred over one giant scroll); "self-contained" means no external *resource
   loads*, not one physical file.

2. **Output location: `docs/explainer/` (real projects); `docs/explainer-demo/` (this issue's demo).**
   Sits beside `docs/architecture/` (the source) without being owned by Cartographer. The demo for #61
   is committed to `docs/explainer-demo/` in this branch so the method is evidenced; f1Brainz is the
   READ-ONLY source and is never written to.

3. **Page structure: overview → subsystems → boundaries/dependencies → decisions.**
   - **Overview** (`index.html`): what the system is, the subsystem list, the freshness stamp/banner,
     and a top-level dependency picture.
   - **One subsystem page per packet**: the packet's purpose, key modules, boundaries, and the "why"
     narrative — map truth first, then a light code read for color where the packet is thin.
   - **Boundaries/dependencies** view: the structural edges (who depends on whom, cross-region
     constraints) rendered as a readable graph/adjacency, sourced from the map's relationships/overlays.
   - **Decisions** view: one card per decision record, the choice and its rationale, linked from the
     subsystems they govern.

4. **Generator stays method-in-skill; the freshness stamp/check is the one small script.** The site is
   generated by an agent following `skills/docent/SKILL.md` (read map truth in a fixed order, then write
   the inline HTML) — no large generator program to maintain, matching the constellation norm that the
   agent does the judgment work. The **one** exception is `scripts/docent_freshness.py`: a deterministic
   staleness check is the core value proposition and an agent eyeballing hashes is exactly the error we
   must not ship. A ~exit-code tool clearly beats prose here (stated call, per the launch-order
   pre-ruling), and it is cross-platform where a shell `sha256sum` pipeline is a Windows hazard.

5. **Freshness contract: SHA-256 digest over the sorted source-map file set.**
   - The **stamp** is `sha256` over the concatenation of `(repo-relative path, file sha256)` for every
     source-map file the site is built from, sorted by path: `index.md`, `packets/**`, `overlays/**`,
     `decisions/**`, and `generated/map.json` **when present**. Hashing the *source artifacts* (not only
     `map.json`) is deliberate — f1Brainz has no `generated/map.json`, and the site is built from the
     packets/overlays/decisions directly, so those are what "fresh" must track.
   - `docent_freshness.py stamp --map-root <dir>` prints the current digest (the generator embeds it).
   - `docent_freshness.py check <site> --map-root <dir>` recomputes the digest, compares it to the one
     embedded in the site, and **exits nonzero when they diverge** (stale) — usable in CI or a reconcile
     hook.
   - The site **self-renders a STALE banner**: the embedded stamp plus a small inline script/marker make
     divergence visible to a human opening the page, not only to a tool. (The site cannot recompute the
     digest from `file://` without the source tree, so the banner reflects the stamp captured at
     generation and is authoritative for "which map this site was built from"; `check` is the live
     divergence gate.)

6. **Regeneration: on-demand, with a soft pointer from Cartographer reconcile.** The human runs the
   docent skill to (re)generate. Cartographer's reconcile doctrine gains **one sentence** noting that a
   published explainer site goes stale on a reconcile and can be regenerated with docent — a pointer, not
   a hard dependency (Cartographer never depends on, or edits, docent output).

## Install / test wiring

- `skills/docent/SKILL.md` is auto-discovered by `install_constellation.py::discover_skills()` (walks
  `skills/<name>/SKILL.md`) — no installer structural change needed for discovery.
- `SKILL_SCRIPT_BUNDLES["docent"] = ("docent_freshness.py",)` bundles the freshness tool into the
  installed skill's `scripts/` (same mechanism as cartographer's `build_architecture_map.py`).
- `SKILL_REFERENCE_BUNDLES["docent"] = _GLOBAL_ORCHESTRATOR` — docent reads Cartographer truth, an
  orchestrator-tier read; this also ships `windows.md` (the tool/file-generation host hazards apply).
- `tests/test_install_constellation.py::SKILL_NAMES` MUST gain `"constellation-docent"` (several tests
  assert the full installed set against this hardcoded list) plus an assertion that the docent script
  bundle installs. `tests/test_docent_freshness.py` unit-covers the stamp/check tool.
- No new install-time template **token rewrite** is introduced (freshness-normalizer mirror invariant,
  issue-48 lesson): the freshness script is bundled by path, not referenced via a `<…-skill-dir>` token
  that would need mirrored normalization.

## Out of scope

No Cartographer map is added to this repo (absent by design). No SPA/build toolchain, no live server, no
marketing page. No edits to f1Brainz. No changes to engine/lessons/triage/handoff/LATITUDE files (fenced
to sibling issues).
