Packet: src/utils — Configuration and Constants

status: currentlevel: containersrc/utils/confidence: highstruct:utils

Detail (from the Cartographer packet)

Responsibility

YAML-based configuration management, centralized constants, F1 calendar logic, driver ID mapping, and environment detection. Used widely across src/data/, src/evo_predictor/, and supporting packages.

Key Modules

config.py Loads configs/default.yaml. Manages project paths (PROJECT_ROOT, DATA_DIR, CACHE_DIR). Generated artifact paths consolidated under outputs/; see docs/OUTPUTS.md. Default values for missing config. Provides Config singleton.

constants.py Centralized constants:

  • F1 calendars (2022–2025) via get_calendar(year)
  • Sprint weekend lists via is_sprint_weekend(year, gp_name)
  • Session types via get_weekend_sessions(year, gp_name)
  • DNF_POSITION = 30 (sentinel for did-not-finish/non-classified; intentionally above foreseeable F1 field sizes)
  • Tire compounds, analysis constants (MIN_CLEAN_LAPS, LONG_RUN_THRESHOLD)
  • Database config, rate-limiting settings, validation thresholds

f1_calendar.py Calendar helper logic (race weekend queries, sprint weekend detection).

ids.py Driver ID mapping between FastF1 and Ergast. Handles code translations and aliases.

environment.py Environment detection utilities, plus physical helpers such as estimate_air_density_kg_m3 (consumed by evo practice_preprocessor).

simplification_limits.py Canonical simplification-limits checker (py -m src.utils.simplification_limits); the project's required complexity gate for Python changes under src/ and tests/ (see TESTING.md).

utilization.py — Resource-utilization policy core (#356) F1-agnostic policy that decides how hard the machine is pushed without changing what is computed. Public surface: UTILIZATION_LEVELS = ("background", "balanced", "max"); the frozen ResourcePlan(level, n_workers, threads_per_worker, priority); resolve_resource_plan(level, *, physical_cores=None, available_mem_gb=None, mem_per_worker_gb=1.0) (maps a level to a plan, enforcing n_workers × threads_per_worker <= cores with a non-user-facing RAM auto-cap logged only when it binds); init_worker(threads_per_worker, priority) (module-level/picklable ProcessPoolExecutor initializer — sets OMP/MKL/OPENBLAS/NUMEXPR env, guarded torch.set_num_threads, best-effort OS priority via psutil); and run_jobs(jobs, worker_fn, plan, *, on_complete=None, fail_fast=True, logger=None). run_jobs reassembles results in input order and short-circuits to a plain in-process loop when n_workers == 1 (no pool, no pickling) so it reproduces the sequential path exactly; the pool path tears down before re-raising the first worker error wrapped with the failing job's identity (JobExecutionError). Holds no mutable module-level state and imports no domain (DB/calendar/evo) concepts; the only third-party import at module load is psutil (torch is imported lazily and guarded inside init_worker). Consumed by the evo gold cycle and sampled backtest, and by the two standalone parallelizable scripts (scripts/build_rolling_compound_priors.py, scripts/run_sampled_runtime_comparison.py).

FastF1 touchpoints (Data region). f1_calendar.py calls fastf1.get_event_schedule() and config.py enables the FastF1 cache. These are the only FastF1 touchpoints outside src/data/; they sit in the Data region and are not reached from analysis/scorer/adapter/predictor code, so the DB-only-analysis constraint is preserved.

Config Files

  • configs/default.yaml — database, caching, logging
  • configs/strength_config.yaml — driver strength weights
  • configs/simulation_config.yaml — Monte Carlo parameters
  • configs/strategy_config.yaml — pick optimization settings
  • configs/pipeline_config.yaml — automation behavior
  • configs/evo/gold_defaults.toml — gold cycle defaults (owned by evo)
