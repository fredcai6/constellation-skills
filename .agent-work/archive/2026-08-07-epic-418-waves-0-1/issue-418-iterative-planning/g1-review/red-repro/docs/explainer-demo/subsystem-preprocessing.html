Packet: src/preprocessing — Windowless Trajectory Estimation

status: currentlevel: containersrc/preprocessing/confidence: highstruct:preprocessing

Detail (from the Cartographer packet)

Responsibility

Windowless full-stint trajectory estimation for physics inputs. Owns a single capability: a Matern-7/2 SDE Kalman-RTS smoother (order=4, per-axis [pos, vel, acc, jerk], white noise on jerk so acceleration is smooth and differentiable) that reconstructs a car's full-stint trajectory (position + velocity + acceleration) with honest posterior covariance and a per-class trust profile. It does NOT persist that output itself — see "Current consumer reality" below for where persistence now actually lives.

src/preprocessing/ contains exactly trajectory/ plus the package __init__.py (which re-exports the trajectory public API). There are no parallel estimation paths: the old windowed-estimator lineage and the separate trajectory_grading/ harness are gone (issue #448); the on-disk artifact.py writer/reader is gone too (pipeline-tighten Task 10, 2026-07-06 — see below).

Boundary (DB-only / cache-only): the FastF1 disk cache is read in exactly one place — trajectory/loaders.py. Every other module in the package consumes data only through loaders.py or through the on-disk artifact. Season-DB truth is read via read-only SQLite URIs (file:<path>?mode=ro), never via DatabaseManager, so no write lock is taken against the canonical DBs. preprocessing imports no src/physics/ symbols — it is upstream of physics, producing the trajectory the physics estimator consumes.

Current consumer reality (physics region): src/physics/ consumes the trajectory estimator by importing loaders, calibration, and physics_adapter directly (e.g. physics/session_fit.py, physics/layer2/session_braking.py, physics/ribbon.py) — the live path re-runs the smoother from raw streams per consumer rather than reading a persisted trajectory back. As of #503, loaders.py is again the sole FastF1-cache reader for the whole physics region: physics/session_fit.py routes its cache fallback through loaders.load_session(weather=True, offline=True) and reads the durable telemetry store (src/data/telemetry_store.py) DB-first (#494), importing no fastf1 of its own. Pipeline-tighten Task 10 (2026-07-06) resolved the artifact-boundary question the #448/#449 design left open — but from the PHYSICS side, not this one: the on-disk trajectory/artifact.py this package used to own is deleted (zero live consumers at deletion time; its schema is documented, retired, in docs/report_schemas/trajectory_trust_profile.md); the persisted-trajectory boundary is now processed_telemetry (src/data/schema.sql), and the writer that activates it — ideal_lap/pvat_writer.write_lap_pvat — lives in src/physics/, not here, specifically because writing to DatabaseManager requires an import this package must never make (see the "Boundary (DB-only/cache-only)" note above, and pvat_writer.py's own docstring). The producer is real and exercised (layer2/session_race.load_race_stints's opt-in pvat_db hook, driven by scripts/export_pvat.py), but nothing yet reads processed_telemetry back — the re-smoothing-per-consumer status quo is unchanged for now. (Recorded as an Open Question in packets/physics.md.)

Physics-region isolation: imports no evo-region packages (evo_predictor, latent_power, compound_prior). Enforced by constraint:physics_region_no_evo_import.

Key Modules

src/preprocessing/trajectory/ — the only subpackage. Self-contained; its __init__.py does not import from src/preprocessing/__init__.py.

dynamics.py Matern-5/2 LTI-SDE per axis: continuous drift/noise matrices and stationary covariance (matern52_sde), discretize to per-step transition + process noise, the 6-state block builder (_block6), and the analytic dense-GP kernel (_m52) for oracle/calibration use. Binding physical constants: SIG_SPD = 0.49 m/s (speed-sensor noise std-dev), NOMINAL_OFFSET = 0.09 s (nominal inter-stream time offset). No FastF1 imports.

smoother.py The estimator core. StintSmoother runs one windowless Kalman-RTS pass over a full stint in O(N) — 8-state [X, Ẋ, Ẍ, J_X, Y, Ẏ, Ÿ, J_Y] (order=4 default, Matern-7/2) with position and speed updates. The order=3 (Matern-5/2) path is retained for the E4-nesting validation and as the legacy model. NSStintSmoother is the non-stationary extension with a state-dependent per-step jerk process variance. Utilities: build_roughness, driver_series, banded_gap. The posterior-query accessors (pos_at/vel_at/acc_at/covariance/nis_series) live in _smoother_query.py as _StintSmootherQueryMixin, mixed into StintSmoother (split out for the file-size simplification limits, issue #302).

#498 additions (both default-off; byte-identical when disabled):

  • Student-t jerk process prior (nu_proc) — when set, the per-step jerk increment smoothness penalty is down-weighted by an IRLS weight w_i = (nu_proc+p)/(nu_proc+delta_i) where delta_i is the standardized squared jerk increment. A large jerk (brake slam) inflates the predict-step Q so the braking knee un-rounds. Requires order>=4; the dataclass Qs_nominal channel plus _proc_weights / _w_proc carry the per-step local Q scaling. nu_proc=None → Gaussian, exact back-compat.
  • kind=3 acceleration pseudo-observation channel — AccelObs dataclass carries parallel (t, ex, ey, a, sigma) arrays (the un-biased, physics-derived acceleration along the (ex, ey) unit direction). Passed to StintSmoother.fit via accel_obs param; merged into the sorted timeline as kind=3 rows that project the acceleration state onto the direction and do a soft 1-row Kalman update. accel_obs=None or empty (len 0) → no kind=3 rows, byte-identical to Gaussian path.

Known bias — decision:smoother_rounds_braking_knee (docs/architecture/decisions/): the Gaussian-smoothness prior flattens acceleration while preserving speed, and rounds the braking speed knee hard enough that the braking peak cannot be recovered downstream from the smoothed trajectory. The #498 estimator-side fix (Student-t jerk prior + kind=3 acceleration anchor) un-rounds the knee on Spa 2023 Q VER (blind Gaussian −34.93 → Student-t alone −38.10 → +kind=3 −37.41 vs raw −38.84); regime-dependent benefit noted — see the decision anchor for current scope and open cross-circuit calibration work.

calibration.py Automatic, target-driven hyperparameter calibration — no hand-tuned gates. fit_stint_hp (PRODUCTION) fits the smoother HP to a chi²-target via scipy.optimize.least_squares; heldout_chi2_full is the full-stint held-out honesty readout; session_offset co-estimates ONE global inter-stream time offset per session; interleaved builds the held-out index split. Loop geometry helpers (fit_line, time_residuals, line_distance, crossing_from_smoother, local_kappa_v2, resid_stats) support sector-crossing residual scoring. calibration.py is now a thin re-export shim (issue #302); the implementation lives in four siblings — _hp_search.py (grid search / chi² objective / fit_stint_hp), _smoother_fit.py (anisotropic + non-stationary HP fitting), _session_offset.py (session_offset), and _loop_geometry.py (E5 loop line-fit geometry) — with the full public + test-patched private surface re-exported so existing from …calibration import … call sites are unchanged.

loaders.py The ONLY cache reader in the package — and, since #503, the single FastF1-cache seam for the whole physics region (the sole module allowed to import fastf1 or touch the FastF1 cache). Read-only DB truth (find_session_id, load_sector_truth, load_all_drivers_sector_truth, stint_span, db_lap_times via file:...?mode=ro) plus offline raw per-driver streams (enable_cache, load_session, load_session_offline, driver_streams, RawSessionStreams). load_session takes weather/offline keywords so physics/session_fit.load_quali_session loads weather-bearing quali sessions through it (cache fallback) instead of importing fastf1 itself. Binding units: X/Y raw decimetres → metres (×0.1), speed km/h → m/s (÷3.6). Decimetre convention verified: Spa 2023 Q VER raw arc 69415 dm × 0.1 = 6941.6 m vs FastF1 Distance 6949.5 m (ratio 9.99 ≈ 10, issue #446/#447). Salvaged from the retired trajectory_grading/{db_truth_loader,offline_loader}.py.

grading.py compute_trust_profile — REPLACES the old pass/fail gates with a structured, per-observation-class TRUST PROFILE: per-stream held-out chi² (pos, spd), a NIS summary (mean/std/p90), and sector-crossing residual stats at calibrated loops. Returns a structured dict and issues no verdict — the caller decides. No FastF1 imports.

hp_store.py (pipeline-tighten Task 14) — persistent cache of per-session smoother HP calibration. HPStore(db_path=DEFAULT_HP_STORE_PATH) is a small, standalone keyed SQLite store (plain sqlite3, no DatabaseManager — its own new db, not one of the season DBs the rest of this package reads read-only), keyed on (year, gp, session_type, driver, order, calibration_scheme_tag). scheme_tag(order, windows) folds the Matern order and the flying-window-union flag (whether windows was non-empty) plus a _SCHEME_VERSION prefix into one tag, so a change to either dimension of "how this HP was calibrated" misses the old row (a cache miss) rather than returning a stale fit under a reused key. An OPT-IN seam: calibration.calibrate_session_hp gains hp_store=None, session_key=None — a cache hit returns the stored SmootherHP without re-running the chi²-target search; a miss runs the search then put()s the result. Either omitted is byte-identical to pre-Task-14. get() restores chi2_pos from NULL back to NaN (SQLite's sqlite3_bind_double rejects NaN, silently binding it as NULL on write). Idempotent on the natural key (INSERT OR REPLACE). Wired opt-in from both physics/session_fit.py's _calibrate_hp_for_driver and physics/layer2/session_race.py's _calibrate_driver_hp — production wiring into a real batch caller (this task's scope was the cache seam itself) is a follow-on.

Removed (pipeline-tighten Task 10, 2026-07-06): artifact.py — the on-disk trajectory-product writer/reader (write_artifact, read_artifact, build_artifact_from_smoother, schema version 1) — deleted; zero live consumers confirmed at deletion (the single-store mandate: processed_telemetry, written by src/physics/ideal_lap/pvat_writer.py, is now the one persisted- trajectory boundary; see "Current consumer reality" above). The schema it wrote is documented, now retired, in docs/report_schemas/trajectory_trust_profile.md.

physics_adapter.py Bridge from a fitted windowless StintSmoother to the physics engine's processed_telemetry DataFrame contract (smoother_to_processed_telemetry). Maps the smoother's 6-state [X, Ẋ, Ẍ, Y, Ẏ, Ÿ] (and its 6×6 posterior covariance) into the physics engine's 9-vector [px,py,pz,vx,vy,vz,ax,ay,az] state with the 45 upper-triangle cov_i_j elements SegmentClassifier reads (z rows/cols zero — the 2D smoother has no out-of-plane motion). Imported by src/physics/ (session_fit.py, layer2/session_*), making it the typed seam between the trajectory estimator and the force layer.

Capability

Windowless full-stint trajectory estimation. Given raw FastF1 streams for a driver-session, produce a smoothed full-stint trajectory (position + velocity + acceleration), an honest posterior covariance, and a trust profile — in-memory, for direct physics consumption (physics_adapter.py) or, when a physics caller opts in, persistence to processed_telemetry via src.physics.ideal_lap. pvat_writer (this package writes no artifact of its own; see "Current consumer reality" above). Automatic chi²-target HP calibration with sector-loop offset co-estimation generalizes across drivers without per-driver tuning, optionally cached per-session via hp_store.py.

Validated: 2022 Spain R, pooled held-out median 22.77 ms (gate ≤ 50 ms), automatic calibration generalizing across 20 drivers (issue #448).
