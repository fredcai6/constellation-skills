## Three additional candidates, observed live during this epic's own Admiral run

Ruled by me as in-scope for your filing pass (issue **filing** is a delegated class; issue *closing*
is not, and you close nothing). File these alongside the ones #425 already names. All three were
observed on 2026-08-05 on `.agent-work/epic-418/`, and that work area plus its
`ADMIRAL_LOG.md` and `spine.json.journal` are on disk in the main checkout as your evidence.

**1. The stop rail does not recognise a filed `refresh-request` as a sanctioned idle.**
With evidence `e-latitude-2` attached and `current` printing `REFRESH REQUESTED: latitude`, the Stop
hook still reported `SPINE MID-FLIGHT … do not end your turn to wait` and demanded a `block` or a
`waive`. The reach-up primitive in `global-everyone.md` §reach-up and the stop rail **disagree about
what a legitimate stop is, and the reach-up side loses** — the doctrine-sanctioned exit is treated as
abandonment. Workaround used: convert the governed idle into `block … --authority human`, which the
rail does accept. This is the **#235 shape**; the epic's own spec already records it as hit live
multiple times, and #425 is the issue tasked with recording it. Link the prior occurrences.

**2. A hard governor trip freezes the `DIGEST:` that the handoff it forces depends on.**
The engine writes why-records on `advance`. A HARD trip blocks `advance`. So the event that forces a
handoff is the same event that prevents the brief from being updated. A fresh agent cold-starting
from `current` alone read *"nothing about the epic's substance is settled yet"* **after** the latitude
contract was confirmed — it would have re-run the entire interrogation. Mitigated here by hand, with
a `STATE_NOTE.md` carrying an explicit "the DIGEST is stale, read this instead" section. The
mitigation is manual and depends on the tripped agent noticing; nothing enforces it. **Note in the
filing that workstream B (#420) is evaluating whether this falls inside its channel-completeness
scope** — if B claims it, this filing becomes B's cross-reference rather than a separate defect.

**3. `.spine-rail-binding.json` accepts a junk key from an unexpanded shell variable.**
The binding file for one harness session contained a key literally reading
`C:\Programs\constellation-skills\$E` — an unexpanded shell variable that reached the hook's argument
parser and was stored as if it were a real path. Nothing validated it. Related, and worth one line in
the same filing: `_scan_active_spine` globs `.agent-work/*/spine.json` for active leases and callers
take the **first** match in glob order, so an abandoned run's stale lease silently shadows the live
one — that is what happened here, and it cost this run real time before epic-267 was closed.

**Also confirm whether #425 already carries this one**, and add it if not: `file_issue_set.py`'s
github adapter passes issue bodies via `--body` on the command line, so bodies over ~32K fail on
Windows with `WinError 206`. The fix shape is `--body-file` plus a temp file.
