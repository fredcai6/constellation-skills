## #488 — resolve_gauge_path dedups by distinct gauge path

**Defect.** `scripts/hooks/gauge_writer_hook.py:resolve_gauge_path` appended one
candidate per binding, no dedup. The caller (`handle_post_tool_use`) treats 2+
candidates as ambiguous and writes nothing. So the check counted bindings, not
distinct gauge paths — exactly the live Admiral shape (session `db1a42c1`,
`.agent-work/.spine-rail-binding.json`): one session_id bound to
`epic-418-redux/spine.json` AND `epic-418-redux/latitude-interrogation.json`,
both parented under the same work dir, both resolving to
`epic-418-redux/gauge.json`. That Admiral's own governor went dark for a whole
wave.

**Before-state (pasted).** New tests added to `tests/test_gauge_writer.py`
(`test_resolve_gauge_path_dedups_two_bindings_resolving_to_one_path`,
`test_admiral_shape_two_spines_one_work_dir_produces_a_reading_not_a_skip`),
run against the pre-fix hook:

```
FORCE_COLOR= NO_COLOR=1 python -m pytest -q tests/test_gauge_writer.py -k "dedups_two_bindings or admiral_shape"
FF.
2 failed, 1 passed, 67 deselected
```

`resolve_gauge_path(proj, "s1")` returned **2** candidates for the same-dir
Admiral shape (should be 1); `handle_post_tool_use` wrote **no** `gauge.json`
(ambiguous-binding skip fired for a pair that resolves to one file).
`test_admiral_shape_negative_direction_genuinely_different_paths_still_skip`
already **passed** pre-fix — confirming the negative direction was never
broken, only the positive one.

**Fix.** `resolve_gauge_path` now dedups candidates by distinct `Path`
(order-preserving, first-seen wins) before returning them. No change to
`handle_post_tool_use`'s `len(gauge_paths) > 1` check, no change to
`scripts/checklist_engine.py` (fenced to #465), no change to the binding key
shape.

**After-state.**

```

```

Both directions verified:
- Same-work-dir two-binding pair (Admiral shape) → **one** candidate → a real
  `gauge.json` reading, no `gauge-skip.json`.

## #489 — REVISED_SPEC.md fixture glob fails loudly on 2+ matches

**Defect.** `tests/test_verify_spec_confirmed.py`'s
`ConfirmPhaseRegressionOnALiveSpec._fixture` took `matches[0]` from
`sorted((ROOT / ".agent-work").glob("*/spec-revision/REVISED_SPEC.md"))` with
no signal a second match existed. A second epic work area (archived run
restored, parallel redux) would make the test silently verify the wrong spec
and still pass.

**Before-state (pasted).** Ad hoc repro, exact pre-fix logic, against a
synthetic two-fixture tmp `.agent-work/` (never touching the real
`.agent-work/epic-418-redux` tree):

```
matches found: ['epic-alpha\\spec-revision\\REVISED_SPEC.md', 'epic-beta\\spec-revision\\REVISED_SPEC.md']
current code silently returns matches[0] content: 'SPEC A - the WRONG one under test\n'
second match epic-beta\spec-revision\REVISED_SPEC.md is silently dropped -- no signal, no error
```

**Fix.** Extracted `_resolve_revised_spec_matches(agent_work_root)`: returns
the sorted match list unchanged for 0 or 1 matches; raises `AssertionError`
naming every match found for 2+. `_fixture` now delegates to it, preserving
the existing `skipTest` on zero matches. New tests (`tmp_path`-only, never the
live tree) cover zero, one, two, and three matches, asserting the raised
message names every match.

**After-state.**

```

26 passed
```

Includes both pre-existing live-regression tests
(`test_live_revised_spec_still_passes_confirm`,
`test_live_revised_spec_also_passes_review`) against the real, still-single
`.agent-work/epic-418-redux/spec-revision/REVISED_SPEC.md` — unaffected by the
refactor.
