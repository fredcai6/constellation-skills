## Mission A — issue #488: the gauge writer counts bindings, not distinct paths

**Every Admiral run that drives its `latitude` step properly blinds its own context governor for the
rest of the run.** Not a race, not a rare interleaving — it fires on the *correct* behaviour.

`resolve_gauge_path` (`scripts/hooks/gauge_writer_hook.py:257-264`) appends one candidate **per
binding**, with no dedup:

```python
candidates = []
for entry in sid_bindings.values():
    spine_path = entry.get("spine") if isinstance(entry, dict) else None
    if not spine_path:
        continue
    candidate = Path(spine_path).parent / "gauge.json"
    if _is_contained(candidate):
        candidates.append(candidate)
return candidates
```

The caller (`:530-541`) treats `2+ candidates` as ambiguous and writes `gauge-skip.json` instead of a
reading. **So the count is of bindings, not of distinct gauge paths.**

**Measured live, on the Admiral that dispatched you.** Session `db1a42c1` is bound to exactly two
checklists in `.agent-work/.spine-rail-binding.json`, **both its own and both legitimate**:
`epic-418-redux/spine.json` and `epic-418-redux/latitude-interrogation.json` — the Interrogator survey
the Admiral spine's `latitude` step *requires* it to drive. Both resolve to the identical path
`.agent-work/epic-418-redux/gauge.json`. Observed:

```

gauge-skip.json  {"reason": "ambiguous-binding", "candidate_count": 2}                    <- refreshed live, hours later
```

That Admiral ran an entire wave with **no governor coverage**, while reporting the governor's trip
band as its crews' largest drag.

**Why the skip's own rationale does not apply here.** The skip exists (#261) to prevent
**misattribution**: when two genuinely different top-level agents share one `session_id`, the hook
cannot tell whose activity produced the latest usage record, so it declines to guess. That is sound —
**and vacuous when both candidates are the same file.** There is no whose-reading-is-it question when
either answer writes to one place.

**Acceptance:**
- Two bindings resolving to **one** gauge path produce a **reading**, not a skip.
- Two bindings resolving to **genuinely different** gauge paths **still skip** — #261's protection is
  not weakened.
- A test covers **both** directions, including the specific Admiral shape (a spine plus its own
  latitude survey in one work area).

Likely `len(set(candidates))` — but **choose the fix against the test, not the test against the fix.**

## Mission B — issue #489: a fixture glob that cannot signal a second match

`tests/test_verify_spec_confirmed.py:252`:

```python
matches = sorted((ROOT / ".agent-work").glob("*/spec-revision/REVISED_SPEC.md"))
```

With one match this is correct. With two — a second epic work area, an archived run restored, a

from.

**Flagged independently by both reviewers of PR #470**, neither having seen the other's verdict.

**Acceptance:**

## What connects them — and the trap in both

Both are instances of **a check that cannot fail: a signal whose value is identical in the healthy
and the defective world.** Wave 2 found four across four subsystems; these are two of them.

Which means the trap is recursive, and it is the whole point of this dispatch: **a test that only ever
runs against the healthy case is itself a check that cannot fail.**

So for each mission, **build the defective world and observe the current code getting it wrong**, then
fix, then observe it right. Concretely:

- **#488:** construct a binding registry with two entries resolving to one path. Show the *current*
  code skipping. Fix. Show it reading. Then construct two entries resolving to *different* paths and
  show it still skips.
- **#489:** construct two matching fixture files. Show the *current* code silently returning the first.
  Fix. Show it failing with both names listed.

**Paste the before-state in both cases.** A return that shows only the green after-state has not done
this dispatch.
