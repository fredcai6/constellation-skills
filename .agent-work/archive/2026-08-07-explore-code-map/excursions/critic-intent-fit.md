# Cold critic — lens: intent-fit

Crew: constellation/explore-code-map/review-critic-intentfit/critic/attempt-1
Target: `.agent-work/explore-code-map/DESIGN_SPEC.md` (read cold; no exploration artifacts read)
Code checked to verify claims: `evidence/x13/checks.py`, `evidence/x13/checks2.py`, `evidence/x13/checks2_output.txt`, `evidence/x13/checks_output.txt`, `evidence/x13/render_map.py`

Stated intent under test: *"A codebase should be traversable without reading it... replaces that function [the human-authored Cartographer map] with a derived map... Done feels like this: a dev agent picking up an issue is handed the specific map pages for the work, learns the blast radius before its first edit, and the map rebuilds itself in under a minute."*

| ID | Lens | Severity | Finding | Disposition | Reason |
|---|---|---|---|---|---|
| IF1 | intent-fit | BLOCKING | The spec claims to replace the Cartographer *function*, but its own evidence says the derived map reproduces only the structural spine, and x1 measured that spine at **7% of the curated map's text**. The other 93% — boundaries, judgment, why — is assigned to the comment grammar (§3), whose extraction pass **does not exist** (build queue #4) and whose entire authored corpus today is **six tags in one f1Brainz PR**. So the design as specified retires a map and replaces roughly a fourteenth of it, with the replacement for the rest unbuilt and unadopted. The spec never states what the Cartographer map still owns in the interim, nor a gate at which it may be retired. Either narrow the intent to "replaces the structural spine, Cartographer keeps judgment" or write the retirement criterion (e.g. tag coverage threshold + extractor shipped) and hold the claim until it is met. |  |  |
| IF2 | intent-fit | MAJOR | The headline intent ("traversable without reading it", "instead of spraying whole files into context") is contradicted by the design's own governing content rule. §6: "a page must lead with what a `grep` plus one file-read does *not* give... Never restate what reading the file shows." A page built to that rule is by construction insufficient on its own — the agent must still open the file. §7 concedes this outright: the implementer "uses the map for cross-file questions and source for within-file ones." What the design actually serves is *cheaper cross-file navigation and blast radius*, which is a defensible goal but a different one, and it changes what success looks like: context saved per issue is now bounded by cross-file lookups avoided, not by files not read. Rewrite the intent to the goal the design serves, or drop the redundancy rule — as written the two cannot both stand. |  |  |
| IF3 | intent-fit | BLOCKING | The intent's load-bearing promise is that an agent can *trust* the map enough to act before its first edit, and the mechanism that would earn that trust — pipeline stage 4, "Check" — does not check anything. `checks.py` and `checks2.py` contain **zero assertions and no exit code**; they print diagnostics for a human to read, so the spec's "all pass" in the prototype table is unearned and no regression can fail a build. The spec also misdescribes them: §1 names "determinism, ASCII-in-templates, entity reconciliation, spot check", but `checks.py` does ASCII + reconciliation + a spot check with no determinism test, and `checks2.py` does neither — it covers store-only definition sites and function-local imports (defect D4). Worse, nothing anywhere checks `referenced by`, the single most intent-critical line on a page. I confirmed the defect in source: `render_map.py:230-240` sums *all* callers into `n` and `len(callers)` but names only modules other than the defining one, and `checks_output.txt:55` shows the wrong output already rendered ("referenced by: 3 sites in 3 modules" listing two). Determinism does not save this — a deterministically wrong blast radius rebuilds byte-identically forever. The check stage needs assertions with a nonzero exit, and at least one semantic check on referenced-by against an independent source scan (the spot-check code at `checks.py:115-129` already computes one; it just never compares). |  |  |
| IF4 | intent-fit | MAJOR | The intent diagnoses the incumbent as "expensive to keep true, and it drifts" — and the design relocates that drift rather than removing it. Everything derived gets real machinery: determinism, run report, churn measurement, orphan gate. Everything *authored* — the `Assumption:` / `Constraint:` / `Rationale:` / `Rejected:` tags and `[stable-id]` slugs that carry the 89% of "why" x8 measured — gets one doctrine sentence ("The code is truth") and a survival law that governs whether a tag is *consumed*, not whether it is *still true*. §5 builds a whole mechanism for the small case (anchor deleted, ~6 per repo-lifetime) and nothing for the large one (anchor alive, tag quietly false after the code around it changed). A stale `Constraint:` that the map faithfully renders is strictly worse than no map, because the agent was told to trust it. The design needs at least a detection signal here — e.g. flag tags whose anchor entity's fact set changed in the same rebuild, surfaced in the run report the reviewer already reads. |  |  |
| IF5 | intent-fit | MAJOR | Cost was the other half of the intent's case against the incumbent, and the spec never measures its own. "Rebuilds itself in under a minute" covers only the machine stage (38s); §1's own ruling puts **hole adjudication and cleanup** in the same predominant workflow step, and §2/§4/§5 add standing per-PR human obligations: a `rulings.jsonl` line ruled at review for every rename PR, orphan promote-or-die ruled at the deleting PR, duplicate-slug build errors, plus 692 ranked docstring holes already open and a "check holes did not grow" step in §8. None of this is bounded, budgeted, or compared against what the human-authored Cartographer map cost per PR. The design may well be cheaper — but the spec asserts the incumbent's expense as motivation and then declines to price the replacement, so the central comparison the intent rests on is unevidenced. State the expected per-PR human cost and what evidence would show it exceeds the incumbent's. |  |  |
| IF6 | intent-fit | MAJOR | §4 names the mind-map link as "the one external interface that must stay stable", then rests it on the mechanism with the worst adoption evidence in the spec. Concept links ride the author-written `[stable-id]` slug — and §3's first-contact result is six real tags and **zero anchor ids authored**. The fallback for structural links is the symbol path, which §2 explicitly calls "disposable by design", repaired after the fact by hand-written `rulings.jsonl` entries. So the must-not-break interface is: an unadopted mechanism, backed by a deliberately unstable one, backed by manual review catching it. "Minted on demand only" (§3) is the right instinct for cost but leaves nobody responsible for minting the id *before* the mind map needs it. Either make id presence a build requirement for any entity the mind map references (fail the run report on a mind-map slug with no anchor), or state plainly that structural links are best-effort and the mind map must tolerate dangling links. |  |  |
| IF7 | intent-fit | MAJOR | §9 imports a second product and then contradicts the intent inside its own section. A coverage report of "src entities with zero inbound test edges, ranked by call frequency", with a named comparison against `coverage.py`, is a test-gap tool — different consumer, different failure modes, its own limits section — while the intent is traversability and blast radius. Splitting `referenced by` into production vs test callers genuinely serves the intent (it de-conflates the 561 no-inbound entities); the ranked report does not, and it drags `coverage.py` parity into the testing pathways as something this design must now defend. Then the same section proposes to **stop rendering per-entity pages for test functions**, which removes traversability into tests in the section whose premise is that test links are first-class — an agent can no longer answer "what does this test touch" from the map, right after being told test edges matter. The stated benefit ("halves the page count") is not a cost this design has: pages are pull-based, so count consumes nothing; the real defect named is one useless line, which is a render fix. Keep the split, cut or separately ticket the report, and fix the line instead of deleting the pages. |  |  |
| IF8 | intent-fit | MAJOR | Consumption value is the entire content of "done feels like this", and it is the one thing the design has almost no evidence for — while the falsification bar is set so low it cannot fail. Testing pathways: consumption value is falsified by "a run where **every** page is parity-or-worse against grep", so one useful page in one run passes; multi-dispatch value is explicitly deferred to production. The evidence base is a single use trace (5 pages, one issue). Against that, the spec's own trial produced direct counter-evidence it files as build items rather than as intent risk: the agent "read 60 lines of [the top index] and learned nothing" (#2), and the map's referenced-by "nearly shipped a broken `main`" (#1). §7's ratification measures *compliance*, not benefit — map-before-source moved 0/4 → 4/4, which shows agents will look at the map, not that looking helped — and x12 records that pushed generated context can measurably harm (−0.5 to −2% success, +20–23% cost). Replace the vacuous bar with a per-dispatch criterion that can actually fail (e.g. a named fraction of loaded pages must answer the question that motivated the load, judged by the consuming agent's own trace), and run it before the map is wired into the default handoff. |  |  |
