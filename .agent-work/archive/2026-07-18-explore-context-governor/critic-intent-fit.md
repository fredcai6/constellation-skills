| IF1 | intent-fit | BLOCKING | Trip reads the gauge file only "at each gate" (on `advance`), even though the writer updates it on every tool call. A single long-running gate can blow past the HARD threshold with zero checkpoint until the next `advance` call — nothing in the design bounds how much a gate can grow between checks. The host's own ~90% emergency auto-compaction could fire mid-gate before the governor gets a single chance to intervene, defeating the stated goal of handing off "before that point." No mitigation (mid-gate re-check, max-work-per-gate guidance, etc.) is specified. | | |
| IF2 | intent-fit | BLOCKING | The Intent's "biased toward yes" framing is never actually engineered — it is implemented purely as question wording ("stop-by-default question," advisory), and the agent may decline with a one-line reason at zero cost, with no escalation, no tracking of repeated declines, and no consequence short of independently crossing the separate HARD threshold. An agent with momentum to keep working (a known LLM tendency) can rationally decline every SOFT prompt for an entire job. The design has no structural bias toward stopping — only a hopeful prompt — so "biased toward yes" describes copy, not mechanism. | | |
| IF3 | intent-fit | BLOCKING | Why-capture mandates three fields every non-exempt gate — `why_done` / `now_understand` / `next` — but Module 4's cold-start payload is defined as "`DIGEST:` (latest `now_understand`) + `ACTIVE <gate> — <imperative>`." Neither `why_done` nor `next` is cited as an input to the refresh read anywhere in the spec. If they are genuinely unread at the one moment (refresh) that's supposed to justify the whole "continuous why-logging" investment, two of the three mandatory-every-gate fields are filler rather than payoff — the exact question the reviewer is asked to test ("useful cold-start, or filler?") resolves against the design as written. | | |
| IF4 | intent-fit | MAJOR | The digest can be badly stale relative to actual work completed. An explicit `mechanical` marker discharges the mandatory why-prompt with zero content, and "the live digest = the latest non-superseded `now_understand`" — a single string, not a rolling synthesis. A long run of mechanical-only advances leaves the digest pointing at whatever real understanding was last logged many gates earlier. Since a refresh trips on fill, not on content freshness, a fresh agent can cold-start from an understanding that is many completed gates behind the actual state — directly undercutting the spec's own falsifiable test that the resumed agent must not "re-derive the why." | | |
| IF5 | intent-fit | MAJOR | Intent frames this as giving "the fleet" a proactive, portable handoff mechanism, but v1's Gauge is Claude-Code-only, and Trip's fail-safe ("missing/stale = no reading → no advice, never a forced handoff") means the entire proactive mechanism is silently inert on Codex/pi-run agents. Those agents get exactly the untouched status quo the spec opens by naming as the problem (lossy ~90% auto-compaction). "Reach-up refresh stays fully portable" is true but irrelevant without a trigger — reach-up never fires on those tiers. The "fleet" framing oversells what actually ships. | | |
| IF6 | intent-fit | MAJOR | The spec's own kill condition is a continuity-loss comparison against auto-compaction ("if a clean handoff+refresh loses more effective continuity than auto-compaction preserves... the governor is pointless"), but none of the four Testing pathways measure continuity loss or benchmark against auto-compaction's baseline — they test narrower mechanical invariants (refusal-without-why, staleness fail-safe, threshold fencing, one qualitative "didn't re-derive the why" drill). As written, there is no described way to ever detect that the kill condition has fired. | | |
| IF7 | intent-fit | MINOR | Internal tension on whether the motivating problem is live: the HARD band is justified as a backstop that "rarely fires (we are structurally not hitting auto-compacts today)," yet the Intent opens by citing the harness's lossy auto-compaction as the reason the governor exists at all. If auto-compacts genuinely aren't being hit today, it's unclear what live pain is being proactively prevented versus what future risk is being pre-empted — and that distinction matters for how urgently the explicitly-deferred threshold tuning needs to land before the mechanism has any teeth. | | |
| IF8 | intent-fit | MINOR | The claim that "the same mechanism that enables intentional refresh also makes ordinary crash-recovery cheap" leans on crash resume falling back to "today's cold-start" — but this document never characterizes what today's cold-start baseline actually looks like or quantifies how much the why_trail improves it. The "pays for itself even where... a harness can't refresh well" framing is asserted rather than shown within the spec; if it rests on context outside this document, that context should be cited here. | | |
