## Findings first — two corrections to the issue

**H1's description doesn't match the code.** The store's three methods (`write_fingerprint`, `get_fingerprint`, `row_count`) all take `(driver, era, vocabulary, channel, what_measure)`. So `vocab` is *already* a value object (`ClassVocabulary`), and `class_id` is **not** a parameter at all — it spans `vocabulary.class_ids`. The key is a **slot** (5 fields), not a `CellAddress` (6 fields). A `CellAddress` therefore cannot literally be the parameter type as the acceptance criterion words it.

But there **is** a real defect underneath, and it's narrower and sharper than "primitive obsession":

- `write_fingerprint` already constructs a `CellAddress` per class (`store.py:233`), so writes are *incidentally* validated — a malformed `driver`/`era`/`what_measure` raises `ValueError` today.
- `get_fingerprint` (`store.py:255`) and `row_count` (`store.py:298`) construct **no** address. A read with `driver="VER|X"`, `driver=""`, or `what_measure="garbage"` matches zero rows and **silently returns k synthesized `"unresolved"` cells** — indistinguishable from a legitimately-empty slot. That is the hole worth closing, and it's the failure the "malformed-address test" should pin.

## Plan

### H1 — tighten the store's address surface

**Design decision (needs your call, recommendation given).** Three options:

- **A (recommended): introduce a `CellSlot` value object** in `address.py` holding the four loose strings (`driver`, `era`, `channel`, `what_measure`), validated by the same rules as `CellAddress` (non-empty `str`, no `|` delimiter, `what_measure` in the known set). Give it `CellSlot.address(vocabulary_version, class_id) -> CellAddress` and `CellAddress.slot -> CellSlot`, sharing one field-validator so the two can't drift. Store methods become `write_fingerprint(slot, vocabulary, observations, *, allow_unverified=False)` etc. This models the actual key honestly and makes the read path structurally unable to accept a bad address.
- **B: keep signatures, add a private `_validate_slot(...)`** called at the top of all three methods. Zero call-site churn, closes the read hole — but leaves the primitive obsession the issue names.
- **C: accept both** via a compatibility shim. Not worth it in a single-consumer repo.

I recommend **A**. Two sub-decisions inside it:

1. **Do not put `vocabulary_version` in the slot.** The `ClassVocabulary` stays the sole source of `vocabulary_id`, preserving today's semantics exactly and avoiding a new redundant-argument failure mode. (The existing `era` vs `vocabulary.rules_era` mismatch check stays exactly as-is — it's Protected Intent with tests at `test_store.py:129,137`.)
2. **Don't add `channel in FINGERPRINT_CHANNELS` validation.** `CellAddress` deliberately doesn't enforce it today (only `what_measure` is enum-checked), and `fit.py:347` validates channel separately. Adding it in `CellSlot` alone would create drift between the two types, and adding it to both is a behavior change beyond this issue's scope. Note it as a separate candidate.

**Two invariants to preserve carefully:**
- `CellSlot` must **accept** reserved `what_measure` values (they're constructible per `address.py:41-48`); the store's `ReservedWhatMeasureError` refusal on *write* stays where it is. `test_store.py`'s reserved-slot test must still pass unchanged in spirit.
- Check order shifts: address validity now fires *before* the era/vocab and reserved checks. That's the right order (you can't name a slot you can't spell), and no existing test asserts the old ordering — but it's a real change to note.

**Call sites: 57 across 8 files.** Production is small — `fit.py:356` (one write) and `pilot/pipeline.py:257,325` (two duck-typed reads through an `Any`-typed store). The rest are tests (`test_store.py`, `test_fit.py`, `test_bounded_validation.py`) and two scripts (`fingerprint_bounded_validation.py`, `join_bounded_validation_667.py`). Mechanical but broad.

**Leave `FingerprintCell` alone** — flattening it into a `CellAddress` would ripple into `join.py` and `pilot/pipeline.py:281-285`, which read `c.class_id`/`c.mean`/`c.status` directly. Out of scope.

**New tests** (the acceptance criterion), targeting the *read* hole specifically:
- `get_fingerprint` and `row_count` with a delimiter-bearing `driver` → `ValueError`, not k unresolved cells. This is the regression that would have shipped.
- Same for empty-string and non-`str` components, and unknown `what_measure`.
- Confirm reserved `what_measure` still reads fine and still refuses on write.
