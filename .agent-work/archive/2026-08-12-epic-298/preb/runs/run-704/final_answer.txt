## What the planning found

**The duplication is real and the seam is entirely private.** `_axis_means()` (`replication.py:103-128`) and `main_effect_margin_uncertainty()` (`:425-433`) each make one pass over the `(driver, class) → value` grid accumulating a per-driver-row and per-class-column aggregate. Nothing outside the module references `_axis_means` (grep: 3 hits, all in-file). Importers are just two scripts plus the pilot's lazy `run_panel`.

**The non-obvious constraint: "byte-identical" is a real engineering requirement, not boilerplate.** Float addition is order-sensitive, so a shared helper preserves bits only if per-axis accumulation stays in grid-iteration order, the grand mean keeps its *own* left-to-right pass (never re-derived from concatenated driver rows, never `fsum`/`np.mean`), and per-axis list order survives because `_main_effect_se` feeds it `np.std(ddof=1)`.

**The sharpest critic finding (CC1):** an identity harness built from exactly-representable floats (0.5, 0.25) is bit-identical under *any* summation order — it would pass a genuinely reordered implementation and prove nothing. The plan now requires non-exact values and a demonstration that the harness actually fails when order is perturbed.

**Two things I could not verify:** every test invocation this session was permission-blocked, so #704's "tests stay green" premise is unmeasured — the plan measures it at `e0`/`g1` rather than inheriting it. And the cold plan critic wasn't cold (no subagent dispatch available); that substitution is recorded as the plan's largest process debt, alongside the serially-authored design-it-twice candidates.

**Decisions I made in the absence of a human** (each recorded verbatim as it would have been asked, in `INTERROGATION_RECORD.json`): helper returns grouped value *lists*, not sums+counts (the margin caller needs the values themselves for a std); proceed rather than close won't-do, held to a surgical diff; regression scope = all six `instrument_panel` test files + pilot + an exact-equality harness, not the full physics suite.

**Plan shape:** `e0-context` (toolchain probe — the agent-shell `py` is a codex runtime with neither pytest nor radon — plus baseline measurement) → **G1** capture a non-vacuous byte-identity harness against the *unmodified* module → **G2** the one-file dedup, which must pass that harness untouched. The ordering is the proof: goldens captured after the edit would merely encode whatever the new code does.

Explicitly declined: letting `per_driver_demean` skip the means it discards. It's the module's deliberately-wrong negative control and its readability is its value — filed as triage, not taken.
