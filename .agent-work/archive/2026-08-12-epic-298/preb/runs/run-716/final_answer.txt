Both named defects fail *misleadingly*, not loudly — an empty list, indistinguishable from "no crews yet" / "you never archived". So the regression tests must assert the **positive** match; an error-shaped test would pass against the bug.

Two things materially shaped the plan:

- **The fix is in another repo.** Canonical home is `C:\Programs\constellation-skills\scripts\`; `~/.claude/skills/*/scripts/` are install output. f1Brainz needs no source change.

The critic pass changed the spec three times. The most important: my first `_entry_block` rule ("prefer the longest match") returns the **child** entry when a parent id is asked for — it inverted the bug it was meant to fix. Corrected to exact-delimiter-bounded match preferred, substring only as fallback.
