## The headline: two of the issue's three premises are wrong

**H1 is unachievable as written.** `CellAddress` carries six fields including `class_id`. All three store methods — `write_fingerprint`, `get_fingerprint`, `row_count` — are *class-agnostic*: they address a **slot of k cells**, with the class dimension supplied by `vocabulary.class_ids`. Typing them on `CellAddress` would force a meaningless argument.

But the defect underneath is real and worse than "primitive obsession": **write validates, read doesn't.** Write builds a `CellAddress` per class (`store.py:233`), so a bad component raises. `get_fingerprint` builds nothing — `driver=""` or `driver="VER|X"` returns k synthesized `"unresolved"` cells, indistinguishable from a legitimately unfitted driver. That's the silent-wrong-answer shape your own `ORCHESTRATOR_CONTEXT.md` lists first.

Ruling: satisfy the *intent* via a five-field `SlotAddress`, with `CellAddress` re-expressed as slot + `class_id` so there's one ontology and one validator. Hard cutover, no shim.

**H3's premise is false.** `.agent-work/` is **tracked**. `.gitignore` covers `*.pkl`/`*.npz`/`*.db`/`scratch`/`ckpt`/`backtests` under it — nothing for `*.json`. Both named JSONs are **committed** under the archive path, deliberately. tc2's blanket `.agent-work/**/*.json` rule would silently un-track your evidence trail across 664/666/667/669/670. The real risk is different: the 675 script writes to a *bare relative* path into a work area archived on 2026-07-26, resurrecting a stale directory at whatever cwd it ran from.

**H2 is real and its fix works** — verified, not assumed. The editable install is the finder-hook flavour mapping `src` → the MAIN checkout, but `install()` **appends** to `sys.meta_path`, so `sys.path.insert(0, repo_root)` wins.
