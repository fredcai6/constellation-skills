## The blocker, and the fix

### B1 as the reviewer stated it

`test_worktree_from_spine_walks_to_the_nearest_agent_work_ancestor` asserted the
derivation's return equals `str(worktree)` in six places. The new derivation
returns a **`normcase`-folded** path; `str(tmp_path / ...)` is unfolded. On
Windows `normcase` lowercases and rewrites separators, so the two differ for
**every** `tmp_path` — the drive letter alone guarantees it. The predecessor test
passed there, so the diff turned a green Windows test red, and `windows-latest`
is red at baseline, so nothing would ever attribute it.

**I accept B1 without reservation.** It reproduces, and my own attempt-2 Evidence
8 named the hazard and then failed to apply it to this test. The correction to
that scoped null is below.

### The fix

One helper, spelled from the predicate the implementation applies, placed
directly above the test (`tests/test_spine_rail.py:874`):

```python
def _derived_form(path):
    """A directory in the normalized form `_worktree_from_spine` returns it in.
    ...
    Same construction as `tests/test_worktree_derivation.py`'s `_expected()`,
    which is what pins these two files' expectations to one rule.
    """
    return os.path.normcase(os.path.normpath(str(path)))
```

Three edited lines carry all six comparisons — one direct, one inside the
four-element `now_owned` loop, one for the nested sandbox:

```python
assert sr._worktree_from_spine(str(spine)) == _derived_form(worktree)
    assert sr._worktree_from_spine(str(path)) == _derived_form(worktree), path
assert sr._worktree_from_spine(str(nested)) == _derived_form(sandbox)
```

I used the sibling's construction rather than inventing a second one, as the
handoff required. `tests/test_worktree_derivation.py` was **not** touched.

**The class is swept, not just its six instances.** Every other assertion this
diff adds to `tests/test_spine_rail.py` is boolean (`is True` / `is False` /
`is None`), so no other platform-inherited path expectation survives anywhere in
the added lines. Checked mechanically over `git diff e36e630b -- tests/test_spine_rail.py`,
not by eye.

### 8. Windows: separators and case folding — **corrected in attempt 3**

- **Separators.** `os.path.normpath` converts `/` to `\` on Windows before the
  walk, and `os.path.split` splits on both separators there. The comparison target
  `.agent-work` contains no separator. Termination is separator-independent: the
  loop stops when `os.path.split` stops making progress (`head == current`), which
  is what `C:\`, a UNC root, and POSIX `/` all do.
- **Case folding.** `os.path.normcase` is applied to **both sides** — the input
  path and the `.agent-work` literal — so the fold is symmetric. On POSIX it is
  the identity on both.
- **Both test files' case expectations are now constructed, never inherited.**
  `tests/test_worktree_derivation.py`'s `_FOLDS_CASE` is computed from
  `os.path.normcase(".AGENT-WORK") == ".agent-work"`, not from `sys.platform`;
  `tests/test_spine_rail.py`'s `_derived_form` applies `normcase(normpath(...))`,
  the same predicate the implementation applies.
- **The Windows-visible behaviour change, named:** the derivation returns a
  `normcase`d path where the old `_worktree_from_spine` returned
  `str(agent_work.parent)` unfolded, so on Windows the derived worktree comes back
  lowercased. Consumers already fold both sides before comparing
  (`spine_rail._same_path`, `checklist_engine.origin_worktree_refusal`), so this is
  consistent — but **g2 should know it before wiring the value into anything that
  compares by raw string.**
- **Deliberately *not* folded: `_is_claim_layout`.** It compares `.agent-work`
  case-sensitively, exactly as the code it replaced did, so on Windows it is
  stricter than the derivation. That is correct: the gate must accept exactly what
  it accepted before, and it never accepted `.AGENT-WORK`.
