## Why this matters now

Before #142, pairwise σ was **structurally decoupled** from the loss (~10–17 near-constant). Student-t ν mainly affected the **mean head** gradient on retro residuals. After #142:

- Term B actively trains σ toward `|residual|` via detached Student-t NLL
- `lambda_sigma_nll = 1.0` is gold default (`configs/evo/gold_defaults.toml`)
- G4 smoke already logs `r_over_sigma_p95` / `r_over_sigma_p99` per epoch (`.agent-work/issue-142-sigma-calibration/evidence/g4-diagnostics.jsonl`)

Example G4 smoke trajectory (synthetic retro_delta, ν=4):

| Epoch | r/σ p95 | r/σ p99 | σ mean |
|-------|---------|---------|--------|
| 1 | 1.65 | 1.75 | 0.50 |
| 5 | 1.58 | 1.64 | 0.52 |
| 10 | 1.97 | 2.50 | 0.51 |

With ν=4, the Student-t loss is relatively flat for moderate `|r/σ|`; if σ is now **actively shrinking** on confident pairs (especially race-start, Q6 rationale), the effective tail weight may be wrong for some (phase, scope) combinations.

G5 gold retrain showed **aggregate** uncertainty quality improved (near-zero corr modules 4→1, wrong-sign 6→4), but did not validate ν choice per module family.

## Problem

`student_t_nu: float = 4.0` is a **global constant** in `LatentPowerConfig` applied to:

- Quali / race_start / race phases
- Driver / constructor scopes
- Race-weekend vs recent-history evidence families

No instrumentation exists in **production gold diagnostics** to answer: "Are we saturating the Student-t kernel?" or "Would lower ν help σ calibration on tight-residual modules?"

## Proposed work

### Phase 1 — Instrumentation (required before tuning)

Add persistent `|r/σ|` percentile telemetry to gold-cycle / training diagnostics:

- Per module, per epoch (or per checkpoint): p50, p90, p95, p99 of `|mu - target_mu| / sigma`
- Split by phase (`quali`, `race_start`, `race`) and scope (`driver`, `constructor`)
- Write to module training diagnostics JSON and/or gold details report
- Baseline capture on promoted bundle `gold_cycle_260530_042533_2018thru2024`

### Phase 2 — ν sensitivity (research)

- Sweep ν ∈ {2, 3, 4, 6, 8} on **smoke or single-module** slices first
- Primary readouts: σ dynamic range, corr(σ_π, log_loss), pairwise log-loss (no regression)
- Focus modules: race-start (small residuals, Q6), quali (higher variance)

### Phase 3 — Per-(phase, scope) ν (if justified)

If instrumentation shows systematic misfit:

- Extend config: e.g. `student_t_nu_by_phase: dict[str, float]` or per-module override in gold TOML
- Update ADR 0008 with decision rationale
- Full gold retrain only if ν changes materially affect promoted bundles

## Acceptance criteria (minimum viable)

- [ ] `|r/σ|` percentiles emitted for real gold training (not smoke-only)
- [ ] Documented interpretation guide: what p95 thresholds suggest ν is too high/low
- [ ] One-page analysis comparing ν=4 baseline vs at least one alternative on ≥2 module slices
- [ ] Recommendation: keep global ν=4 **or** proceed to per-phase tuning issue
