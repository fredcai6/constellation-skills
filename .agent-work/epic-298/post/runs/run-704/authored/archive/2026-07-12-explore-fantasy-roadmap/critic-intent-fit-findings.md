# Critic Findings — Lens: intent-fit

| ID | Lens | Severity | Finding | Disposition | Reason |
|---|---|---|---|---|---|
| IF1 | intent-fit | BLOCKING | Track 2's priority list omits the project's own already-documented highest-leverage lever on the exact stage the spec says holds "effectively all headroom." `docs/evo/prediction_ceiling_and_priorities.md` (current, post-dates #420) states the remaining quali-stage gap is localized to the standalone `race_weekend` head's per-context evidence weighting and explicitly routes the fix to #375 (the context-conditioned shared net), calling it "the real Thrust A core" and "where the leverage is" — with a targeted stage-1 probe (#414) already showing a cheap anchor recovers 68-72% of that gap. #375 does not appear anywhere in the Track 2 ordering (decomposition study, DNF hazard, #513→#450 physics, ephemeris, new-regs) or the exploration digest's stocktake. Since fantasy points live almost entirely in quali ordinal skill (the digest's own claim), passing over a scoped, partially-validated, same-stage lever in favor of unweighed bets on other stages is a direct intent-fit gap: it risks spending the "reliable ASAP" week on lower-expected-value channels while the highest-value one sits unmentioned. | | |
| IF2 | intent-fit | MAJOR | The "centerpiece" physics bet is sized against a stale headroom number. The exploration digest frames the quali stage as "0.74 sign-acc vs ~0.81 data-only ceiling" — implying ~6-9pp of open gap for #513→#450 to chase. But `docs/evo/prediction_ceiling_and_priorities.md` §7.6.4 shows the cross-channel pace anchor (#420) is already active in the promoted gold bundle (`quali_pace_anchor_enabled = true` in `configs/evo/gold_defaults.toml`, confirmed live in `gold_cycle_260608_043414` and its successor `gold_cycle_260612_054059`), and the #335 regen already scores 0.7765 (LOSO) / 0.7616 (OOS 2025) against ceilings of ~0.806 / ~0.764 — roughly 70% of the framed gap was closed in production before this push started, weeks ago. Sizing the physics bet's expected fantasy-point yield (and its rank as item 3 of 5) against the old, wider gap risks over-crediting it relative to alternatives that were compared against the same stale baseline. | | |
| IF3 | intent-fit | MAJOR | The chosen north-star metric optimizes the wrong shape of "winning" for a ~20-player single-season tournament, and the spec defers the one capability that would fix it. D4's north star is simulated league placement plus average fantasy pts/race — an expectation-maximizing metric. But `src/fantasy_scoring/beam_search.py` already implements four objective lanes (mean score, risk-adjusted score, balanced score, max-score) — the codebase already treats variance-aware lineup selection as a distinct, first-class concern from mean pts/race. The spec's own exploration record lists "tournament-variance lineup strategy" as an open thread explicitly deferred to "later drills," yet the metric it uses to judge every other bet (placement via average points) is exactly the metric that is blind to that variance strategy. Winning one season against ~20 correlated rivals is a single-champion outcome, not an average-points contest; a model tuned purely to D4's metric could improve every gate in this spec while never taking the boom/hazard-avoidant lineup choices that actually move Tommy from 2nd to 1st in the weeks that decide the season. D2 also doesn't say which beam-search lane feeds the Belgium shakedown output, so the very first real deliverable makes this load-bearing choice by default rather than by design. | | |
| IF4 | intent-fit | MAJOR | Sequencing risk on the "reliable ASAP" clock for the spec's own shakedown vehicle. D2's `race-week` command — the sole means of producing the Belgium (7-days-out) prediction — has its interface explicitly "deferred to cut-time with design-it-twice mandated" (Untaken roads). Design-it-twice is a real multi-option interface exercise, not a formality; deferring it to the issue's planning gate leaves a compressed window to run that exercise, build the command, wire collect → sampled-predict → lineup optimizer → emit, and validate the whole path end-to-end before FP1-3 land Friday and quali locks. The spec states the falsification bar ("falsified if the command cannot produce a submittable list + explainer from Friday FP data before quali lock") but never reconciles it with the interface-design deferral that sits directly upstream of meeting that bar. | | |
| IF5 | intent-fit | MINOR | D3's own stated purpose for running the decomposition study first — "cheap; steers the rest," explicitly said to "reprioritize items 2-5" — is undercut by the Sequencing section, which commits capacity to items 2 and 3 (DNF channel, #513) mid-week, i.e., before the decomposition study's channel-value table can have landed and actually done any reprioritizing. If the study is meant to steer, work on the items it's meant to steer starting in parallel from day 1-2 risks sinking effort into bets the study might show are the wrong ones. | | |
| IF6 | intent-fit | MINOR | D4 keeps Brier "primary for gold-vs-gold comparisons per existing project doctrine," but the entire push's target is fantasy delta-sum + bingo scoring — a materially different loss shape (magnitude of top-10 positional error, not calibrated probability). `docs/evo/prediction_ceiling_and_priorities.md` §2 states outright that "fantasy scoring is applied downstream and is explicitly not a target for honing the model." Every model-promotion decision in this push (retrain-with-2026, DNF channel, physics features) is gated in part by a metric orthogonal to the thing the push exists to win; a change that helps fantasy pts/race but is Brier-neutral or Brier-negative could be rejected at the gold gate the spec otherwise treats as settled doctrine, without the spec ever flagging the tension. | | |
| IF7 | intent-fit | MINOR | D3 item 2 (DNF/reliability hazard channel) is framed as a from-scratch build whose "model shape... decided at cut time by A/B," but `docs/evo/prediction_ceiling_and_priorities.md` §1.4/§3 already characterizes reliability as near-memoryless (a team/season prior, one-sided position-loss tail) and names existing `predictive_t` / per-site tail machinery as the intended lever for exactly this. The spec doesn't acknowledge or reconcile with this existing characterization, risking the workstream re-deriving what's already measured instead of building on it. | | |
| IF8 | intent-fit | MINOR | The Confirmation block's "Assumptions exercised" / "Assumptions accepted untested" fields are blank. The push's entire quantitative case (853 vs 766 vs 674 pts/season, the 7.5 pts/race target, the 0.74/0.81 quali-ceiling framing) appears nowhere in the repository outside this spec and its own exploration artifacts — no independent doc, committed report, or test carries these numbers. IF2 already shows one of them is stale. Leaving the untested-assumptions field blank means the confirm gate can close without ever recording that these load-bearing figures were checked against anything but the exploration cycle's own arithmetic. | | |
