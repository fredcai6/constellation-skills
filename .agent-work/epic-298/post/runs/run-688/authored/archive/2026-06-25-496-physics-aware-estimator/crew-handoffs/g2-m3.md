# G2 Spike M3 — Decoupled 1D physics-constrained longitudinal filter

(Read `g2-COMMON.md` in the same dir first — shared context, scoreboard seam, output rules.)

## Thesis
Root cause (`decision:smoother_rounds_braking_knee`): along-track POSITION is timing-jitter
dominated (~3.5 m), so the only good longitudinal observable is the SPEED channel — and the 2D
position-smoothness prior corrupts it in transients. M3 stops asking the 2D position smoother to
carry longitudinal dynamics at all: estimate longitudinal motion with a SEPARATE small 1D
physics-constrained filter on the speed channel, with a process model that PERMITS friction-limited
sharp decel. The 2D smoother keeps geometry/heading; longitudinal `a_long` comes from the 1D filter.

## Concrete approach
- Build a 1D state-space filter along time on the speed channel: state `[v, a]` (or `[v, a, jerk]`),
  observation = raw speed `inp.v` (and optionally raw `a_long_raw` as a soft obs). Process model:
  near-constant-acceleration with a JERK process whose variance is permitted to be large during
  braking (so a sharp onset is a predicted feature), and a physics CONSTRAINT that decel is bounded
  by a friction-limited braking frontier `a >= -(a_b + b_b·v²)` (fit `a_b,b_b` from the raw braking
  arc, or use a generous physical bound ~6 g). A Kalman/RTS or MAP fit is fine; keep it 1D and small.
- Output `a_long` = the filtered acceleration state at `inp.t`. (For the scoreboard only `a_long`
  matters; you do NOT need to touch `StintSmoother` at all — this is a parallel estimator.)
- Your `VariantFn` runs the 1D filter on `inp.v` (+ `inp.a_long_raw`, `inp.regime`) → `a_long`.

## Why it's evolutionary, not a reorg
You ADD a small parallel 1D longitudinal estimator; you do NOT replace the 2D position smoother and
do NOT do a full joint trajectory+parameter collocation (that heavier path M6 was rejected). The
2D smoother still owns geometry. State this boundary in your result.

## Invariant note
M3 does not use the kind=3 anchor channel at all, so `decision:two_cycle_external_anchor_design` is
not directly touched — but note that M3's `a_long` IS derived from the raw speed observation (the
un-biased source). Say so.

## Watch for
- This is the most from-scratch mechanism — keep the 1D filter SMALL and well-tested on a synthetic
  step (a known sharp decel) before the real cases. Report the synthetic sanity check.
- Tuning the jerk process variance is the crux: too small re-rounds the knee (same disease), too
  large = noise. Report the sweep. Bahrain is the prime target; Monaco ringing should be near-zero
  for a 1D speed filter (no 2D position coupling to ring) — that is M3's potential structural edge.
