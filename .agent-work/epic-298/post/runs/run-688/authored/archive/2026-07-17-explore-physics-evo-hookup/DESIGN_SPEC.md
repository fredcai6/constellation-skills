## Intent

The fundamental point of this project is to **beat human players at fantasy F1**. The current push replaces raw lap-timing features — which are noisy, carry misleading signals, and already lean on questionable corrections — with **physics-derived capability features** as the inputs to the evo predictor. The physics model is valuable in its own right, but round 1's job is narrow and concrete: **produce the most believable and honest physics features we can, and prove whether they help predict qualifying** through an honest A/B against the current model, scored ultimately by fantasy points per race versus actual results.

"Done" for round 1 feels like: physics stability the user trusts (future work is refinement, not interface rehash); a stage-1 estimator consolidated from today's five-view spike into one coherent architecture; honest features flowing into evo through a clean seam; and a measured answer to "does this beat what we have," reportable either way. The neural module that consumes these features, driver-affinity consumption, race-distance corrections, and weather/news are explicitly **round 2+**.

## Chosen design

### Program shape — "C-start into B-spine" (design-it-twice outcome)

Three plan structures were designed in parallel under distinct constraints and compared on risk-retirement order, evidence earliness, thrown-away-work exposure, and integration risk:

- **Plan A (tracer-bullet-first):** fastest working pipe; costs a throwaway storage layer built twice and an early result that may be recent-history signal in disguise.
- **Plan B (foundation-first):** most trustworthy, builds the architecture to solve the hardest problem once; but the make-or-break question (does physics beat the ceiling) isn't tested until the very end, and it is slowest to first signal.
- **Plan C (earliest-signal parallel):** the decisive correlation screen needs no new code and runs on existing data immediately; risks track divergence and assumes many parallel hands.

**Chosen: a named hybrid (user-confirmed).** Open with **Plan C's free probes** (correlation screen + SQ coverage on existing data, this week, zero new modeling) to buy the go/no-go information cheaply — serving the user's own "test physics now, cheaply" instinct (#601 Wave-7A banner) and the standing "chase every avenue" philosophy. Then build on **Plan B's disciplined foundation-first spine** (segmentation → four-layer state model → unified-basis refit → FP → feature view → injection → A/B), because the intent is *believable, honest features* and the user's rule is "build the architecture to solve the hardest problem." Borrow exactly **one** move from Plan A: the moment stage-1 exists in rough form, force one real weekend through the whole pipe to shake out integration — but reuse the real contract, not a throwaway (avoiding A's one genuine write-off). The correction this forces onto the exploration board: FP work is the *deepest* piece but not the *first* — the cheap screen comes first, stated explicitly.

- **Per-section approval:** program shape — approved by user (AskUserQuestion, 2026-07-17).

### Phase plan (the epic decomposition)

**Phase 0 — Free probes + baseline lock + early integration tracer (no new modeling).**
- Run the **correlation screen** (Wave 7A) as an **informational refinement probe, not a go/no-go**: join existing 2019–2026 weekend-relative Q estimates to evo's own quali errors, residualized against evo's existing recent-history features (a **partial** correlation, not a raw one), with a **pre-registered primary axis or fixed composite** to avoid fishing across 11 axes. It clarifies where signal lives and refines the approach; it does **not** answer the ~0.80-ceiling question (that is G1's job) and does not gate the build.
- Run the **early wide-σ A/B checkpoint (accepted reorder, F8):** push the *existing* five-view estimates through the injection seam with deliberately widened σ (honestly accounting for the uncoupled covariance x7 found), and read G0/G1 once. Informational: it tells us whether the raw estimates already carry signal, so Phase 3's unification is refined by evidence rather than taken on faith. The full unification still proceeds — this checkpoint informs it.
- Run the **integration tracer (moved earlier, F15):** push one real weekend end-to-end through the *real* contract using the raw five-view estimates as the feature source, decoupling seam/wiring risk from architecture risk. Re-run after Phase 2/3 if the architecture changes materially.
- Run the **SQ coverage probe**: invoke the existing Q estimator on sprint-qualifying sessions (never done; plausibly compatible).
- Lock the "beat this" numbers: x4's relative-normalization floor and x7's five-fracture checklist.
- Fix the **headless A/B deadlock (#623)** — a hard prerequisite for every later gate.
- **Informational scope-checkpoint (F1):** after these probes, the human reviews the reads and may cut/defer scope into the capability ledger. This is a decision point, not an automated kill; the full build is the default and cuts are the human's explicit choice. *Proves:* whether physics carries signal evo lacks, and where; whether the seam wires; whether coverage optimism survives contact.

**Phase 1 — Segmentation substrate + circuit time-share rollup.**
- Extend `segment_classifier` from hard per-sample tags to **soft/fractional property-class membership** over a continuous descriptor substrate; class count support-driven; per-corner identity deferred. Corners are mixtures over classes (reusable correlation structure). Add straights as first-class segments and a lateral-g/radius axis; produce the per-circuit regime time-share rollup.
- Serves two consumers: the **observability router** (which segments carry evidence for which basis parameters) and the round-2 circuit-demand/affinity substrate (banked, not chased).
- *Gate (F12 — falsifiable check added):* rollup reproduces known circuit character (sanity), **plus** a held-out-circuit class-membership stability check OR agreement between the soft-membership rollup and an independent circuit-character proxy (e.g. lap-time variance by corner type, or published downforce-level ratings). The substrate that Phases 2/4 load-bear on must have at least one way to fail, not only an eyeball check.

**Phase 2 — Four-layer weekend-state model on Q.**
- Build the state model carrying, explicitly and each with honest σ: **(1) explained physics** (density from measured per-session pressure, mass/fuel), **(2) structured within-session evolution** (a smooth grip latent — track rubbering evolves within a session, not weekend-constant), **(3) field-car common-mode state** (solve relative, then re-anchor onto a best-estimate field car so absolute development still accrues — the "cake and eat it" two-stage decomposition), **(4) car signal** (deltas off the field car).
- *Gate (F6 — pinned):* re-run x4's exact methodology on this model's output on a **held-out weekend split** (weekends not used to fit the model's hyperparameters); the pinned statistic is the **median convergence-speed ratio across axes**, and the model must **beat the relative floor on a majority of axes (≥7/11)** by a margin outside noise — not an in-sample, cherry-picked-axis win. Secondary: the density layer must *explain* known cross-track differences (e.g. Mexico altitude) rather than need an ad-hoc correction.

**Phase 3 — Unified-basis refit with full covariance (x7 closure) + σ honesty (#506).**
- One physical basis solved across the whole lap; the fingerprint routes observability, never partitions into a car×zone matrix. The five x7 fractures: grip triplet cross-coupling, dual-CdA reconciliation, `a_long` reconciliation, shared-trajectory-noise propagation, and cross-view covariance persistence. σ-honesty (#506) folds in here — a real persisted joint covariance *is* the honest-σ mechanism, not a bolt-on floor.
- *Gate (F5 — pinned):* **cross-view covariance persistence is a NON-DEFERRABLE minimum product** — Phase 3 does not pass until the store holds real cross-view covariance terms (every downstream σ claim and the honesty curve depend on it). The other four fractures may close as a fix OR defer with a **quantified downstream-impact bound** (not just a label). An undecided fracture, or a deferral without an impact bound, is a phase failure.
- **Parallel non-blocking track:** 2026 two-state (Z/X) latent-mode aero fit, using already-delivered dependencies (allowance-zone layer, CdA evidence scorer, RegulationEra fix). Gates only 2026 rows entering the feature view; validate the basis on 2019–2025 dry Q first.

**Phase 3b — Driver utility on the same basis (produced, not consumed).**
- Utility as per-unit-class access of the car envelope; race-history prior, weekend update; per-axis expression nuance (≈zero on power-to-weight, style dims possible, corners dominate). Banked for round-2 consumption.
- **Construction (F4 — made explicit to avoid circularity):** car capability is a POOLED latent estimated from many observations (season-pooled per-constructor envelope), fit *independently* of any single driver-weekend. Driver utility is then how well the driver accesses that separately-estimated latent — it is NOT a per-lap `observed ÷ capability` division. Because capability comes from the pool and utility is measured against it, the recomposition check is not tautological.
- *Gate (F4):* utility must be validated against a **held-out** slice — fit on a subset of a driver's laps/sessions, check that the recomposition (and the per-axis structure: corners dominate, power-to-weight ≈ 0) **replicates out-of-sample**, not just that the scalar product reconstructs the laps it was fit on. Directional sanity vs. driver reputations is a smell test only, never pass/fail. Named limit: no external driver-utility ground truth exists; the held-out replication is the substitute.

**Phase 4 — FP extension (#513) — the deepest piece.**
- `fp_mass()` and per-lap latent state (fuel mass, engine mode, run purpose) with directly-observed compound; grip-class apex speeds as the mass-robust anchor; power-to-weight extracted from the confounded straight/traction classes; sandbagging → **wider σ, never bias**. The weekend car-state chain FP1→FP2→FP3→[parc-fermé step]→Q with process noise for setup tweaks, and a **learnable per-team parc-fermé reaction step**. Continuous representativeness weights (nothing binary-dropped).
- The reframe: FP is a *weak* car-performance demonstrator but a *strong* driver-utility demonstrator; its main product feeds 3b, car capability is a heavily-downweighted byproduct that nudges the season-pooled estimate.
- **Representativeness is a property of the OBSERVATION, not the session (F10):** value is assigned to a lap by its *observed properties* — compound, inferred fuel/mass state, run purpose — wherever that lap occurs. "FP3 usually matters most" must be an *emergent consequence* (FP3 happens to hold the most quali-representative laps), never a hard-coded session weight; if a team quali-sims in FP2, that lap earns the weight instead.
- *Gate (F10 — pinned control):* FP × regime coverage map with quantified σ vs the Q baseline; the learned observation-representativeness weighting must **beat a "weight purely by clock-distance to Q" baseline** on held-out weekends — otherwise it has merely rediscovered the calendar, not learned representativeness. A known sandbagging weekend should visibly discount.

**Phase 5 — As-of-stamped feature view (the product contract).**
- Four record types: weekend-state / car-basis posterior (full covariance, session-chained) / lap evidence / **as-of-stamped feature view** (the only evo-facing surface). MODEL_VERSION keyed, append-only, constructor grain (per-entry divergence banked). 2026 rows appear only after the Phase-3 aero mini-gate.
- *Gate:* append-only contract test (a version bump never mutates a prior row — the "contract freeze" end-state as a testable property) + as-of leakage test (a post-FP1 view provably cannot see FP2/FP3/Q).

**Phase 6 — Prototype injection (direct-BT field, prototype only).**
- Wire the feature view into the field solve as one precision-weighted source behind a manifest toggle (anchor pattern). v1 prototype; the neural-module end state is round 2. *Gate:* wiring exists, unit-tested, gold pipeline runs bit-identical with the toggle OFF (regression safety, not a value claim).

**Phase 7 — A/B harness (the gates), integration bullet folded in.**
- The integration tracer already ran in Phase 0 (moved earlier, F15); this phase is the full evaluation: **G0** correlation-with-evo-errors → **G1** quali sign-accuracy + Brier vs baseline and the ~0.80 FP-data ceiling → **G2** fantasy pts/race (the decision metric). Three as-of cutoffs (post-FP1/FP2/FP3) make the **honesty curve** a computed check, not an eyeball: **prediction-interval coverage at each cutoff must fall within a stated tolerance of nominal** (F14) — a post-FP1 feature whose stated σ is too tight shows up as coverage below nominal. 2022–2025 dry walkforward scored, 2019–2021 appendix, wet flagged and excluded.
- **Gate posture (F1/F11):** every gate is reportable either way and results are *informational* — they refine the architecture, they are not a program go/no-go. A stall sends the finding to the implicated upstream phase; there is no automated kill (the architecture is the deliverable), but the human owns the informational scope-checkpoints where deferral into the capability ledger is decided.

## Testing pathways

- **Correlation screen (Phase 0):** falsifiable now — if the existing physics axis shows no correlation with evo's quali errors beyond what recent-history already carries, the seam is wrong; reweight toward affinity/σ layers (not a kill).
- **State-model floor (Phase 2):** falsified if the four-layer model fails to beat x4's relative floor on x4's own metric — meaning the extra layers aren't doing real work beyond weekend-median subtraction.
- **Basis unification (Phase 3):** cross-view covariance persistence is non-deferrable and must close as a fix; the other four fractures close with a before/after number or a deferral carrying a quantified downstream-impact bound; an undecided or unbounded-deferral fracture is a phase failure.
- **Representativeness (Phase 4):** falsified if the weighting cannot derive "FP3 most representative" from held-out data, or fails to discount a known sandbag weekend.
- **Contract (Phase 5):** append-only and as-of leakage are checked by construction, not inspection.
- **Injection (Phase 6):** gold runs bit-identical with the toggle off.
- **The gates (Phase 7):** G0/G1/G2 each reportable either way; the honesty curve across three as-of cutoffs is the anti-overconfidence check (a post-FP1 feature that *hurts* exposes bad σ).
- **Deferred to later drills:** neural-module consumption, driver-affinity/utility consumption, race-distance corrections, weather/news, 2026 live-season rollout, per-entry spec divergence, cross-weekend cross-driver upgrade pulls.

## Capability ledger — scope the informational checkpoints may defer (F1)

The full build is the deliverable; the architecture is the goal. But the Phase-0 informational checkpoints (and any later informational read) may lead the human to *defer* pieces if an early read says they aren't the near-term unlocking capability. This ledger names what is deferrable and what capability is left on the table if it is — so nothing is silently lost. Deferral is always a human decision at a checkpoint, never automatic, and every deferred item stays a tracked round-1.5/round-2 issue.

| Deferrable piece | Capability left on the table if deferred | Why it's still long-term necessary |
|---|---|---|
| Phase 3b driver utility (produce) | No round-1 loss (it's produced-not-consumed); defers the round-2 driver-affinity unlock | The basis is incomplete without it; affinity is the user's "huge piece" |
| Phase 3 full fracture closure beyond cross-view covariance (the non-deferrable minimum) | Some duplicate-physics information stays uncoupled (grip triplet, a_long split); σ slightly less tight | Multi-view redundancy reducing uncertainty is the whole unification thesis |
| Phase 1 soft-membership richness (vs. coarse router-only tags) | Round-2 affinity substrate is coarser; observability routing still works | Corners-as-mixtures is the reusable correlation story affinity needs |
| Phase 4 FP depth beyond the `fp_mass()` coverage fix | FP feeds car-capability as a nudge only; the driver-utility demonstrator is thinner | FP-as-driver-utility is the root-cause affinity path |
| 2026 two-state aero | 2026 live-season features stay single-θ_D (wider σ) | Required before physics features can honestly touch the active-aero era |

Whatever the checkpoints actually defer will be recorded here at decision time, so the final round-1 scope is explicit about its own gaps.
