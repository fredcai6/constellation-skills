## Map-reconcile staleness (CartoRecon, 2026-07-24)
A PR-time cartographer reconcile done against the PR's ORIGINAL base goes stale if the PR later gets post-review EXPANSION commits — the reconcile documents a state the merge no longer matches (here: Ship I's 74bfc6aa reconcile ran on 27b6eac9..HEAD, missed the a83d843a/807556b7 expansion → map falsely claimed the real extractor "not built"). LESSON: a cartographer reconcile must be (re)verified against the FINAL merged commit, not the base it was authored on — either re-run it as the last pre-merge step, or (as done here) do a consolidated post-merge pass. Pairs with the general "verify against current state, not the state when written" discipline.
