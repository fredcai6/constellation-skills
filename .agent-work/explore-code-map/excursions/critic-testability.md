# Cold critic — testability lens

Crew: `constellation/explore-code-map/review-critic-testability/critic/attempt-1`.
Read: `DESIGN_SPEC.md` only, plus the prototype files it names, to check claims about the code.

| ID | Lens | Severity | Finding | Disposition | Reason |
|---|---|---|---|---|---|
| TS1 | testability | BLOCKING | The named check suite has no failure state, so no Testing-pathways row that routes through stage 4 can ever go red. `evidence/x13/checks.py` and `checks2.py` are print-only scripts: no `assert`, no nonzero exit, no recorded baseline, no threshold. They exit 0 whether the numbers are healthy or catastrophic. The spec's "all pass" in the prototype table means a human read printed output once. Concretely: `checks.py:71-93` prints "store positions with no supplement entity: 28" and "same position, different symbol (D2): 251" as informational lines, and section 8's "check holes did not grow" has no stored baseline to grow against (`render_report.json` currently reports `holes: 8583` of `14998` entities, 57 percent, and nothing anywhere records that number as the line). The suite also hardcodes `ROOT = C:\Programs\f1Brainz` (`checks.py:9`) and a single hand-picked spot-check file and function (`checks.py:98,110`), so it cannot run on the repo it is meant to guard. Productionizing needs assertions with committed thresholds before any pathway row is meaningful, not a port of these scripts. |  |  |
| TS2 | testability | BLOCKING | Determinism, the spec's cleanest falsifier ("any non-empty diff on unchanged source"), has no implementation and is made unsatisfiable by another ruled decision. Section 1 stage 4 attributes determinism to `checks.py`; that file contains no rebuild-and-diff code at all, only the non-ASCII scan, reconciliation, and spot check. Separately, section 2 mandates "a committed run report per rebuild", and the prototype's report carries wall-clock fields (`render_report.json`: `load_sec`, `render_sec`), so a byte-level diff of two builds of unchanged source is non-empty by construction. The design must choose: exclude the run report from the determinism diff, in which case the one artifact the reviewer is told to trust is the one thing determinism never covers, or leave the check permanently red until someone disables it. Neither is stated. The "double-build byte-identical" measurement cited for `render_map.py` is therefore an uncommitted manual observation, not a pathway. |  |  |
| TS3 | testability | MAJOR | Section 4 is called "the one external interface that must stay stable" and it has never been exercised, has no row in the Testing pathways table, and contradicts section 2. `render_map.py:378-380` writes `ids.jsonl` as an empty file by construction, with the comment that f1Brainz carries no anchor comments. So zero ids exist: duplicate-slug build error, the orphan gate, the `rulings.jsonl` redirect, and the claim that the sorted file's git diff *is* the id-motion report are all unbuilt and unfalsified, on the interface the spec itself says cannot be allowed to break. The contradiction: `ids.jsonl` lines are specified as `{"id","s","q":{file,line}}` while section 2 rules "no positions in the committed store" precisely because positions are the churn that poisons diffs. If `ids.jsonl` is committed, every id below an inserted line moves on every edit, which is the failure section 2 exists to prevent; if it is not committed, the id-motion report cannot exist. Either way the measured 1.2x churn number excludes it, because the file was empty when churn was measured. |  |  |
| TS4 | testability | MAJOR | Defect D2 is scoped in the build queue as a future anchor problem ("fatal once anchors rely on symbol identity"), but it is corrupting the `referenced by` line today, and no check would notice. `render_map.py:231` resolves callers as `inbound[alias[key]]`, and `alias` (`render_map.py:102-112`) maps each supplement entity to the *store's flattened* symbol. `checks_output.txt` records 251 positions where the store symbol differs from the qualified supplement name, for example store `src.compound_prior.neural_rate:WearRateNet.forward_rate` against supplement `..._build_wear_rate_net.WearRateNet.forward_rate`. Wherever a nested and a top-level definition flatten to the same store symbol, their inbound caller sets merge, and both pages show the union. That is a wrong-attribution bug in the exact signal build-queue item 1 calls "outsized trust impact", and the only evidence offered against it is a source scan of one hand-picked function (`checks.py:117-129`). The pathway table has no row for inbound-edge attribution; entity reconciliation checks definitions, not edges. D2 belongs ahead of item 1, not behind item 4. |  |  |
| TS5 | testability | MAJOR | The value of the thing being built is measured by a criterion that cannot fire, and every other metric rewards making pages emptier. The "Consumption value" falsifier is "a run where *every* page is parity-or-worse against grep" — a universal quantifier, so one useful page in a hundred passes it — judged by the same agent that just loaded the page, in a run where it knows the map is under test, with no control arm. The spec's own prior art (x12, ETH) sets a much harder standard: success-rate and cost deltas against a no-map arm. Meanwhile the redundancy rule in section 6 ("a page must lead with what grep plus one file-read does not give ... never restate what reading the file shows") is the load-bearing content claim and has no falsifier anywhere. The "Page format" row tests only ASCII, and that scan is close to vacuous: `checks.py:48` marks a non-ASCII page line explained if any collapsed docstring string is a substring of it *or* it is a substring of any docstring string, matched against thousands of fragments, which is how 2,718 non-ASCII lines produced 0 unexplained. Net effect: churn ratio, median page length, and page count all improve as pages carry less, and nothing measures what is lost. Add a control-arm comparison, or at minimum a per-page recoverable-from-source audit, before the register's minimality is treated as validated. |  |  |
| TS6 | testability | MAJOR | Churn boundedness has no threshold, no unit, and one data point, on the change type that flatters it most. The falsifier reads "a small source change producing large map churn" — neither "small" nor "large" is quantified, so nothing can be judged against it. The single measurement (98 map lines against 84 source lines, 1.2x, 38 of 16,222 pages) came from edits confined to a module, where the design's own bounding argument holds trivially. The adversarial case is one the design predicts is common enough to need a hand-authored redirect table: renaming a widely-referenced symbol rewrites the `referenced by` line on every caller's page and shifts every id in `ids.jsonl`, and it was never measured. Also note two queued items move this number in opposite directions (item 2 adds a second index tier, item 3 halves page count), so the 1.2x figure will not survive the build queue and there is no re-measurement gate. |  |  |
| TS7 | testability | MAJOR | The extraction oracle is blind to the predicates that caused it to be chosen, and the falsifier has a clause that lets any miss be reclassified rather than fail. The spec records that SCIP was demoted specifically because it "emits zero WriteAccess for Python" — so the `writes` predicate has no oracle at all, and `contains`, `documents`, and `param-of` are equally unlikely to be oracle-covered. The falsifier then reads "a symbol SCIP resolves that the AST pass misses, *outside the named inference-rule gaps*", and 9.26 percent of references are already unresolved with 95 percent of those in one named class (`dispatch-unknown-base`); a miss that lands in an exempt bucket is not a failure by construction. Nothing measures edge recall: reconciliation compares definition sites (`checks.py:58-93`), not the reads/writes/calls edges that the map's whole value rests on. The pathway needs a hand-labelled edge sample with a fixed recall floor per predicate, including the predicates SCIP cannot see. |  |  |
| TS8 | testability | MAJOR | Staleness of the authored layer is undetectable, and staleness is the exact failure the design cites for replacing the Cartographer map. Derivation removes drift from the structural facts, but section 2 keeps a hand-authored `<name>.py.md` prose file per source file, section 3 adds hand-written `Assumption:`/`Constraint:`/`Rationale:`/`Rejected:` tags, and section 2 adds hand-authored `rulings.jsonl`. All three can go stale exactly the way the old map did, and the spec's answer is doctrine ("the code is truth ... when code changes because an assumption changed, the comment changes") plus a survival law that is a claim about human behaviour over time with no measurement plan attached. The "Deferred" note excuses this on the grounds that "no staleness-harm measurement exists in the field either", which is an argument about the literature, not about whether this build can detect its own rot. A cheap detector exists and is not queued: hash the tag's enclosing entity span at extraction and flag on the next rebuild any tag whose anchor body changed while the tag text did not. Without it the design ships the predecessor's failure mode in a smaller box. |  |  |
| TS9 | testability | MAJOR | The coverage projection is falsified at the wrong granularity, and the queued page policy removes the surface where the error would be visible. The falsifier is "systematic disagreement beyond the named indirection limit" against `coverage.py` on one known module — an aggregate comparison that passes comfortably while individual entries are wrong. But the consequential harm is per-entity: section 9's stated purpose is to de-conflate *unused* from *untested* among 561 zero-inbound entities so that someone acts on the split, and the acts are "write a test for this" or "delete this, nothing uses it". A false `tested by: none` caused by fixture or helper indirection, which the section admits credits the helper, drives both wrong. Build item 3 then stops rendering per-entity pages for test functions, removing the pages on which a mis-attributed test edge would show up. The pathway needs a per-entity confusion count against `coverage.py` with a false-negative ceiling, not a module-level agreement check. |  |  |
| TS10 | testability | MINOR | Section 7 is already shipped on this branch, has no row in the Testing pathways table, and the evidence cited for it measures compliance rather than benefit. "Loading the skill flipped map-before-source from 0 of 4 to 4 of 4" establishes that agents visit the map when a skill tells them to; it says nothing about whether the dispatch produced a better outcome, and it is the same class of behavioural-compliance signal that the exploration record elsewhere treats sceptically. ToolFailBench naming the failure "Tool-Skip" names a problem, it is not evidence this fix helps. Since the two-tier handoff and the Map entry point line are live code, the design can regress here silently: there is no measurement that would notice if handing subagents named starting pages made dispatches slower or worse. |  |  |
