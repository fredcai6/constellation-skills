# Critic findings — simplicity / YAGNI

Cold read of `DESIGN_SPEC.md` only, plus the prototype files it names. No access to the exploration record beyond the spec's own digest.

| ID | Lens | Severity | Finding | Disposition | Reason |
|---|---|---|---|---|---|
| SY1 | simplicity | BLOCKING | The spec never says which on-disk representation is committed, and the answer decides whether an entire layer can be deleted. Three exist in the prototype run: `statements.jsonl` (141 MB), the section-2 `derived/` tree of `<name>.py.jsonl` + `<name>.py.md`, and the rendered `map/` tree (16,223 files, 51 MB). Section 2's headline rule — no positions in the committed store, because a 3-line edit rewrites ~450 position-bearing lines — is defeated if the pages are committed, because every page carries a position: the sample page `map/src.physics.layer2.estimate_store/EstimateStore.upsert.md` line 2 reads `method, src/physics/layer2/estimate_store.py:414, 11 lines`. Every line-number shift in a file rewrites line 2 of every entity page in it. If instead the pages are NOT committed and are built on demand, then agents cannot read the map without running the build, and the position-free `derived/` store is redundant with `statements.jsonl` plus a cache. Pick one committed representation and delete the other two from the design; as written the spec buys the churn argument in one layer and pays it back in the next. | | |
| SY2 | simplicity | MAJOR | Section 4 (identity and the mind-map interface) is machinery with zero instances and no live consumer. `map/ids.jsonl` renders empty in the prototype — `render_map.py:378-380` writes an empty string with the comment that f1Brainz carries no anchor comments yet. Section 3 confirms first contact authored zero anchor ids. The single named consumer, the mind map, is a separate system that does not exist. So `rulings.jsonl` is a hand-maintained redirect table for external references that have never been made and therefore cannot yet have broken; the duplicate-slug build error guards a namespace with no members; and the run report's rename tracking reports motion of ids that do not exist. The spec already rejected serial-number identity on the grounds that its cost exceeds the benefit while regeneration takes 2.3 seconds — that same argument deletes the redirect table and the rename-motion reporting. Smallest version that still serves the intent: define the `[stable-id]` comment syntax now (it is free, author-side, and section 4's real requirement is that the syntax exist before the mind map lands), emit `ids.jsonl`, and stop. Add `rulings.jsonl` the first time an external link actually breaks. | | |
| SY3 | simplicity | MAJOR | Section 2's storage layout is not the thing the prototype builds, which undercuts both the design-it-twice skip and every measurement the spec attaches to it. The prototype emits `map/<module>/<entity>.md` plus `INDEX.md` per module. Section 2 specifies a source-mirrored `derived/` tree with exactly two files per source file. Those are different trees with different fan-out and different diff behavior. The spec's justification for skipping design-it-twice on the remaining interfaces is that they "exist as working, measured prototype code" and that "the build queue's items are diffs against that code, not new interfaces" — that claim is false for section 2, which is a new interface. The consequence is concrete: the 38-second build, the 16,222-page count, the 15-line median and the 98-lines-of-churn measurement are all measurements of the page tree, so section 2 ships with no measurement of its own while the spec's framing implies it is measured. Either drop the `derived/` tree and commit the page tree that was actually measured, or state plainly that section 2 is unmeasured design. | | |
| SY4 | simplicity | MAJOR | Section 6's ruled redundancy rule and the rendered page contradict each other, and enforcing the rule would delete roughly half of every page. The rule says a page must lead with what a grep plus one file-read does not give, and never restate what reading the file shows. The sample page has 17 lines. The title, the `method, path:414, 11 lines` line, the fenced signature block, and `HOLE: no docstring` are all recovered by opening the file at that line — four lines, plus the fence. `calls stdlib: dataclasses.asdict, json.dumps` and `reads stdlib: builtins.str, json (module)` restate imports and call sites visible in the same eleven-line function body. Only `referenced by: 31 sites in 8 modules ...` and `unresolved: 3 calls` clear the bar. This matters beyond tidiness for two reasons: the 15–16 line median is cited as evidence that the format is already lean, and it is only that long because the rule is not applied; and section 1 lists signature, span, and docstring body as the supplement's whole reason to exist, which the rule argues the page should not print. Resolve the contradiction explicitly — either weaken the rule to "do not print prose the file shows" or cut the page to its non-recoverable lines and re-measure. | | |
| SY5 | simplicity | MAJOR | Four tags is more vocabulary than the evidence or the survival law supports. The spec's own survival law says a tag survives when a tool visibly consumes it, and to ship each tag with its consumer — yet the comment-extraction pass does not exist (build queue item 4, itself blocked on D2), and no consumer is named that treats `Assumption:`, `Constraint:`, and `Rationale:` differently from one another. On a page they would all render as why-lines. The measured corpus is six tags, four of them the same kind. `Rejected:` is separable because section 5 gives it a distinct consumer (the orphan gate), and `See:` is separable because it is a link rather than prose. The other three are one tag wearing three hats, and the author burden of choosing between them at write time is real and paid on every comment. Smallest version: ship `Rationale:`, `Rejected:`, and `See:`, and split `Assumption:`/`Constraint:` out only when a consumer distinguishes them. The spec's own open convention gap — where a tag goes when its rationale covers a whole function rather than a line — is a second signal that the grammar is being specified ahead of use. | | |
| SY6 | simplicity | MAJOR | Section 5 specifies four mechanisms for an estimated six events per repo lifetime. A tombstone requires: orphan detection in the re-derivation crawler, a promote-or-let-it-die ruling gate wired into the deleting PR's review, concept-tree anchoring with an `origin` commit pointer, and location-indexed retrieval that surfaces tombstones from map-first plan queries. Each is a build item, a test surface, and a thing a reviewer must be trained to do. At six instances, the entire behavior is obtainable by convention with no code: when you delete a `Rejected:` comment, paste its text where it still applies. Worse, the anchor is the concept tree, which is the mind map — the same unbuilt system as SY2 — so section 5 cannot be implemented at all until a separate project ships, and the spec does not flag that dependency. Cut section 5 to a one-line convention now, and revive the machinery if orphan volume ever exceeds what a human notices at review. | | |
| SY7 | simplicity | MINOR | The supplement is a whole pipeline stage that build queue item 5 exists to delete, and productionizing it first pays for it twice. Section 1 stage 2 is a second full AST walk over the same 1,224 files emitting a second schema (`supplement.json`, 8.6 MB) for kind, signature, span, docstring body, attribute values, decorators and `__all__`; item 5 then folds exactly those facts into the statement schema. Shipping the two-stage shape means writing, testing, documenting, and then removing a stage, a file format, and the "supplement" concept from the design vocabulary. Reordering so the schema merge lands before productionizing removes a stage from the design outright rather than deprecating one later. The spec's own parenthetical calls this "a named build item, not a blocker", which is a sequencing claim it does not defend. | | |
| SY8 | simplicity | MINOR | Section 9 bundles one high-value deletion with two additions of unproven value, and the bundling hides that only the deletion is clearly earned. Stopping per-entity page rendering for test functions halves the page count, needs no new extraction, and removes 85% of a false signal — pure subtraction, ship it. Splitting `referenced by` into production versus test callers is a small render change that by itself resolves the stated problem (561 entities conflating unused with untested). The coverage report is a new committed artifact whose own named limit — static direct-call reachability, fixture and helper indirection miscredited, ~9% unresolved dispatch — means it cannot be trusted against `coverage.py`, which the repo can already run. Ship the deletion and the split; defer the report until someone names a question `coverage.py` does not answer. | | |
