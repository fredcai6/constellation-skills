# Plan Critic: w1-wiring

**Deviation, recorded up front:** the cold-critic contract calls for a critic with no authoring
context. This dispatched context has no Task/Agent tool, so no independent critic agent could be
raised; this pass was authored by the same agent that wrote the plan, reading only
`MISSION_FRAME.md` and `PLAN_ALTERNATIVES.md`'s converged recommendation (not the candidate files, not
the launch order) to approximate a cold read. This is a materially weaker guarantee than a true
independent critic — flagged again in Workflow Feedback — but the findings below were generated by
actually re-deriving objections against the plan text, not by rubber-stamping it.

## Findings

1. **g1's "one row, one evidence string" is unfalsifiable as written.** The plan does not name the
   exact commands the census will run to classify live/unwired/dead, only the sources to check
   (templates, CI, hooks, tests, cross-script calls). A census that eyeballs each script risks
   inconsistent rigor across ~26 rows.
   **Disposition: accept.** Before executing g1, fix a concrete per-script check sequence (grep the
   `command` check blocks, `.github/workflows/*.yml`, `scripts/hooks/`, `tests/`, then
   `grep -rn <script-basename> scripts/ tests/` for cross-script calls) and apply it uniformly; state
   it once in the census document's header so each row's evidence string is reproducible.

2. **g2 (generate_spine.py) risks conflating "no caller in skills/" with "no caller anywhere."**
   The launch order's own grep was scoped to `skills/`. A caller in `scripts/`, `tests/`, or a CI
   workflow would be missed by repeating the same scope.
   **Disposition: accept.** g2's trace must search the whole repo (`scripts/`, `tests/`,
   `.github/workflows/`, not just `skills/`) for `generate_spine` before concluding no caller exists.

3. **g3's "one mechanism covers both" framing pre-supposes #368 and #444 are comparable without
   having read either issue's exact field lists yet.** Deciding "try one check, split only if
   forced" is right per the pre-ruling, but the gate plan does not name what "forced" looks like,
   risking either an under-scoped shared check or an unjustified split.
   **Disposition: accept.** g3 states, before writing the check, the concrete criterion for "forced
   to split": the two field groups live at structurally different site-shapes (e.g. one is a JSON
   schema list, the other is prose+code assertions) such that one grep/AST check cannot express both
   without unrelated special-casing for one of them.

4. **g4 bundles "delete dead scripts" and "author+wire+prove a lint" as alternatives inside one
   gate, but the mission's own honest-null clause makes these mutually exclusive outcomes of the same
   evidence — the plan should say explicitly that g4 executes exactly one of the three outcomes named
   in the Mission's Honest-Null Clause, not "and/or."**
   **Disposition: accept, cosmetic.** Restate in `execute.json`'s g4 imperative that the gate executes
   the single disposition the census supports, not a blend chosen ad hoc.

5. **No gate re-verifies the local pytest suite stays green after g4's changes, even though the
   Inherited Context explicitly names the base-commit green run (3564 passed, 6 skipped) as "the real
   gate."** A deletion or a new lint could silently break existing tests.
   **Disposition: accept.** Add an explicit `pytest` full-suite run (or the smallest correct targeted
   subset plus a stated reason it substitutes for the full suite) as part of g4's own verification,
   not assumed.

6. **The plan names no gate for `docs/CHECK_SCRIPT_CENSUS.md`'s exact commit path/format, risking a
   census that satisfies "committed" without being the stable, greppable artifact the launch order's
   Return Shape wants named.**
   **Disposition: accept, minor.** g1 states the exact path once (`docs/CHECK_SCRIPT_CENSUS.md`) and
   its row format (script | classification | evidence) so `execute.json`'s postcondition can check
   for it mechanically.

## Triage

All six findings accepted into `execute.json`'s gate imperatives below; none rejected or deferred.
No panel was run (see Panel-vs-single record in `PLAN_ALTERNATIVES.md`); a single pass surfaced
enough concrete, actionable findings that a panel was not judged to be adding marginal value.
